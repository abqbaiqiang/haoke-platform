# 导入客户筛选与批量分配 — 2026-09-14

## 背景与操作

本次检查发现本地 513 个精斗云导入客户都处于未分配状态，因此销售账号的“我的客户”为空。导入客户与 CRM 使用同一条客户记录，无需按名称重新新建客户。

老板进入 **客户管理 → 客户归属：未分配**，按名称/编码、等级或标签筛选，勾选客户、选择本页，或选择全部筛选结果；再选择销售负责人、填写分配说明，点击“确认批量分配”。选择全部覆盖多页，单次最多 1000 个客户；超过限制时需要缩小筛选范围。切换筛选条件自动清空选择，翻页保留已选客户。

界面提交前明确显示客户数量及负责人。没有可见客户的销售账号会提示联系老板分配已有客户，新开发客户才使用新增潜客。功能交付不自动将现有客户分给某个演示账号。

## 规则与接口

- `GET /api/crm/customers` 新增 `ownership=unassigned|owned|public_pool` 筛选；在原有后端数据权限基础上进一步筛选，不扩大销售、经理或财务的可见范围。
- `POST /api/crm/customers/batch-assign` 接收 `customer_ids`、`owner_user_id`、`reason`，返回 `assigned_count`。仅老板及备用管理员可用，负责人必须是可分配的有效销售/经理账号。
- 仅批量分配仍处于“未分配”的有效客户；ID 去重后按稳定顺序加行锁、整批预检查、单事务提交。任何客户已分配、进入公海、停用或不存在，整批拒绝，不产生部分成功。
- 重复提交不会重复产生归属记录；已成功分配的 ID 再次提交返回 409，提示刷新。已分配客户的转交仍走现有单客户转交流程。
- 每个客户沿用已有转交服务生成归属历史和审计记录，并设置 `crm_managed`；后续同源、同编码导入更新原客户资料，保留人工负责人。匹配不依赖客户同名。
- 客户负责人只决定 CRM 归属，不自动重写历史订单销售人员或业绩归属；销售业绩仍依赖数据中心的人员映射与销售口径核实。

## 2026-09-14 补充：导入客户进公海与多人认养

- 自迁移 `0006_m5` 起，导入的客户主档（未被 CRM 管理）统一进入公海（`public_pool`），销售在“客户公海”自行认养；导入时如映射了业务员，仍记为主负责人。
- 认养不唯一：同一客户允许多位业务员认养（`customer_claim` 表，客户+用户唯一）。首位认养人成为负责人并接手开放待办/商机；后续认养只增加认养记录，不改变归属。本人重复认养返回 409。
- 客户列表、公海和客户 360 显示“认养人”（认养人可见客户全过程；其他同事只看到姓名）。认养客户自动出现在认养人的“我的客户”。
- 批量分配仍可用：筛选“未分配”或“公海”后勾选分配；已被认养（有认养记录/CRM 管理标记）的客户自动排除，需调整时打开客户使用“分配／转交／公海”。
- 客户列表新增表头“全选本页客户”与每页显示行数选择（10/20/30/50/100）。
