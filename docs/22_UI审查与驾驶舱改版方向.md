# Impeccable UI 审查与数据驾驶舱改版方向 — 2026-09-14

使用 Impeccable v4.3.1（双独立评估：设计总监评审 + 检测器扫描 + 浏览器实拍）审查现有 UI，目标为经营驾驶舱（`apps/frontend/app/overview.tsx`）。评审快照：`.impeccable/critique/2026-09-14T11-24-43Z__apps-frontend-app-overview-tsx.md`。

## 评分与关键发现

- Nielsen 十项启发式：**26/40（Acceptable）**。弱项：系统与现实语言匹配(2)、一致性(2)、灵活高效(2)、极简(2)。
- 移动端 **P0**：390px 视口下文档 scrollWidth=702px，整页横向溢出。
- 检测器 2 项 CSS 反模式：`cockpit.css:63` 圆角卡 3px 顶部强调边；`globals.css:97` 卡片单侧 3px 色边（AI 味最重的特征）。
- 三件值得保留的"产品之物"：指标口径折叠（definition+source+metric code）、未完月斜线柱、"宁可不显示不显示错数"。
- 核心体验问题：环比无方向无基期；"待核实"是死胡同（无入口、不说明核实什么找谁）；团队四行"待核实 0.00 / —"占首屏黄金位；登录森林绿与驾驶舱蓝青双设计语言并存。

## 两套改版方向

### 方向 A：「决策台」——先行动，后数字

定位：老板每天打开几次、在手机上也能处理事情的工作台。

1. 首屏第一条是"今天需要拍板的 3 件事"：待核实数据（点开看哪批导入未核实→一键去核实）、无目标人员、需要关注的客户，每条带处理动线。
2. 第二层为 4 个大数字卡：环比加方向与涨跌色、副行"较 8 月"、卡片可点直达销售分析对应钻取。
3. 团队目标有目标才显示，全缺时折叠一行 + "去设置目标"；"需要关注"零项时隐藏入口。
4. 保留口径折叠、斜线柱、不显示错数三件套。
5. 视觉统一 token（消除双设计语言），移动端单列优先重写（触达 ≥44px、金额不折行、滚动限定在卡片内）。

风险：改动首屏信息架构，需要老板确认"待核实是否真的一天内会去处理"。

### 方向 B：「晨会大屏」——先结论，后细节

定位：办公室电视/晨会投影为第一目标，网页版是它的降维。

1. 一屏、无滚动、≤6 个数：本月销售额（超大字 + 环比方向）、成交客户、订单数、目标完成率（一根大进度条）、数据可信度状态（已核实/待核实 + 核实率）。
2. 超大 tabular-nums 排版，弱化卡片边框堆叠；延续侧栏森林绿做统一强调色（同步解决双 token 问题）。
3. 网页版上半屏即大屏区块，客户贡献/团队明细/财务视图收进下方折叠或标签，默认不渲染零值空态。
4. 每个数字可点钻取（柱→销售分析对应月），口径进 hover/focus 提示。
5. 桌面端改动小（主要是重排+放大），移动端随方向 A 的底座一并修复。

风险：信息密度下降，深度用户（经理）日常要看明细需多一次点击。

### 共同底座（两套都必须做）

P0 移动端溢出修复；统一 `:root` 设计 token（强调色/侧栏色/radius/shadow 二选一）；清理检测器两项 CSS 反模式；空态与零值降噪；侧栏导航 `<button>` 链接化（可中键新开、可复制直链）。

## 建议顺序

无论选哪个方向：先修共同底座（半天级），再做方向实施，最后 `$impeccable polish` 收尾并复跑 critique 看分数变化。

## 2026-09-14 实施记录：方向 B「晨会大屏」已实施

老板选定方向 B。已落地：晨会大屏首屏（信任行 → 超大金额 + 环比方向 → KPI/目标完成率大进度条 → 全宽趋势）、明细折叠、零值区块不渲染、P0 移动端溢出修复（ECharts 宽度跟随 + 容器裁剪，实测 375≤390）、token 统一为森林绿、两处检测器反模式清理、导航链接化。评审基线 26/40 存档于 `.impeccable/critique/`，收尾截图在 `.impeccable/review/`。遗留：浏览器 e2e 回归未跑；"已设目标人员合计"完成率的口径表述待老板确认是否进指标字典（docs/04）。
