# 松茂经营管理平台 V1 页面清单与权限矩阵

**版本：** v0.1  
**日期：** 2026-09-08  
**状态：** V1 页面与权限基线  
**核心原则：** 前端隐藏不是权限。所有数据范围、敏感字段和写操作必须在后端再次校验。

## 1. V1 角色

| 角色代码 | 角色 | 核心职责 | 默认数据范围 |
|---|---|---|---|
| `owner` | 老板 | 全公司经营查看、目标配置、管理决策 | 全部 |
| `manager` | 销售经理 | 管理团队客户、商机、任务、销售过程 | 所属团队 |
| `sales` | 销售业务员 | 客户跟进、待办、商机、个人工作台 | 本人负责客户/本人业务 |
| `finance` | 财务 | 财务报表、应收、数据导入/核对 | 财务相关 + 被授权经营数据 |
| `admin` | 系统管理员 | 账号、权限、数据源、导入、系统配置 | 系统管理；业务数据默认只为运维需要 |

说明：V1 采用“**主角色 + 数据范围 + 敏感字段权限**”，不先做极其复杂的 RBAC 权限树。后续确有需求再扩展。

## 3. 核心页面规格

### 3.1 销售工作台 `/sales/workbench`

**目标：** 成为销售每天使用的入口，而不是“填日报页面”。

首屏包含：

- 月度目标、已完成销售额、完成率；
- 月度工作日时间进度与目标进度差；
- 剩余目标、剩余工作日日均需完成；
- 今日待办计数：待处理/已完成/逾期；
- 推荐工作：超期未跟进、约定今日回访、商机预计成交日期临近等；
- 我的开放商机金额与加权商机金额；
- 最近 5 个客户；
- “快速记录跟进”“新增待办”“新建商机”按钮。

**禁止：** 销售在此手工修改精斗云实际销售额。

### 3.2 客户列表 `/crm/customers`

筛选：

- 客户名/编码；
- 客户类型；
- 标签；
- 负责人；
- 客户等级；
- 最近跟进时间；
- 最近成交时间；
- 是否有开放商机；
- 客户状态（潜客/正式/沉睡/疑似流失等，状态由系统计算或人工标记区分）。

列表建议列：客户名称、类型、负责人、标签摘要、最近跟进、最近成交、本年销售额、下一待办。

### 3.3 客户 360 页 `/crm/customers/{id}`

页面区块：

1. 基本资料：名称、编码、来源、负责人、客户类型、等级、标签、备注；
2. 联系人：老板、采购、财务、行政、决策人等多个关系人；
3. 跟进时间线：方式、结果、资料发送、备注、下一步；
4. 待办：今天/未来/逾期；
5. 商机：开放、赢单、流失；
6. 精斗云经营数据（只读）：累计/本年销售、订单、最近订单、主要购买商品等；
7. 应收信息（有可靠数据后启用）；
8. 客户归属/转交历史（有权限角色可见）；
9. 操作时间线：关键变更留痕。

### 3.4 跟进录入 `/crm/followups/new`

尽量“少输入，多选择”。字段：

- 客户（必填）；
- 联系人（可选）；
- 跟进方式：电话/微信/拜访/面谈/邮件/其他；
- 沟通结果：未接通/已沟通/有明确需求/已报价/等待回复/暂无需求/明确拒绝/成交等；
- 是否发送资料，以及资料类型；
- 简短备注；
- 下一步日期；
- 下一步动作。

规则：有明确下一步时一键生成待办；跟进保存后写 `activity_log`。

### 3.5 待办中心 `/crm/tasks`

视图：今天、本周、逾期、未来、已完成。  
来源：销售自建、经理分配、系统推荐。  
操作：完成、延期、取消、关联客户、关联商机。

### 3.6 商机 `/crm/opportunities`

阶段默认：潜在 -> 需求确认 -> 方案/资料 -> 已报价 -> 谈判 -> 赢单/流失。  
字段：客户、名称、预计金额、预计成交日期、概率、负责人、阶段、下一步、流失原因。

### 3.7 老板经营总览 `/bi/overview`

首屏：经营销售额、财务营业收入、财务毛利率、净利润、现金、应收、存货/库存。  
后续区块：销售趋势、利润趋势、客户变化、业务员目标进度、重大异常、CRM 过程概览。  
经营销售额与财务营业收入必须明确标注不同口径。

### 3.8 团队执行驾驶舱 `/bi/sales-team`

每个业务员展示：

- 月度目标/完成额/完成率；
- 时间进度和进度差；
- CRM 登录活跃工作日；
- CRM 有效活跃工作日；
- 跟进客户数/有效跟进数；
- 待办完成率/逾期数；
- 开放商机/加权商机；
- 当前月节奏预测。

不使用“在线小时”“鼠标动作”等无业务意义的监控指标。

### 3.9 数据中心 `/admin/imports`

包含：

- 上传文件；
- 模板/数据源识别；
- 导入预检；
- 字段映射；
- 错误行展示；
- 确认导入；
- 导入历史；
- 重跑/重算；
- 数据源状态。

### 3.10 集成设置 `/admin/integrations`

V1 页面预留：

- 精斗云：连接状态、非敏感配置、密钥录入入口、测试连接、同步模块、同步日志；
- AI：Provider、Base URL、Model、API Key、启用开关；
- API 未真正接入时，页面必须明确显示“未配置/暂未启用”，不可伪造连接成功。

| 客户联系人 | R/C/U | 团队R/C/U | 本人R/C/U | R | 运维R/U |
| 跟进记录 | R | 团队R/C/U* | 本人R/C/U* | - | 运维R |
| 待办 | R/A | 团队R/C/U/A | 本人R/C/U | - | 运维R |

## 5. 数据范围规则

1. `sales` 默认只能读取 `owner_id = 当前用户` 的 CRM 客户、商机和任务，以及映射到本人销售人员的精斗云销售数据；
2. `manager` 读取其团队成员范围；
3. `owner` 读取全部；
4. `finance` 是否能看客户/销售明细按授权，不因财务角色自动获得所有 CRM 内容；
5. 管理员具备系统运维能力，但“管理员”不等于天然拥有公司经营决策权限，UI 可按需要限制经营驾驶舱。

## 6. 敏感字段规则

以下至少视为敏感字段：

- 商品真实成本、采购价；
- 毛利额、毛利率；
- 公司净利润、现金等财务数据；
- API Key/AppSecret；
- 用户密码哈希。

密钥永不回显明文，日志不得打印。成本/毛利是否给销售经理查看由老板后台配置，默认关闭。

## 7. 删除与审计

- 客户、用户、联系人、商机等核心记录默认软删除/停用；
- 精斗云导入事实不得从 CRM 页面手工删除；需要通过导入重算/来源状态更新处理；
- 客户转交、目标修改、跟进修改、商机阶段变化、数据导入、配置变更均记录审计；
- 审计记录普通用户不得修改。


## V1 实际使用决策（2026-09-11）

公司现阶段仅使用两类账号：`owner`（老板）与 `sales`（普通同事）。本决策为使用方式调整，不改变上文定义的五角色权限模型：

- 老板账号同时承担系统管理员的日常职责（数据导入、人员映射、期间确认、CRM/BI 配置、人员管理）；`admin` 角色保留作为命令行恢复路径，不日常登录。
- 同事账号由老板在"人员管理"页面创建/停用/重置密码，角色固定为 `sales`，数据范围为本人。
- `manager`/`finance` 角色与对应演示账号保留未用；后续公司扩大后再启用，无需代码变更。
