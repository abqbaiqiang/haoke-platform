# 松茂经营管理平台 V1 开发任务拆解

**版本：** v0.1  
**方法：** 按 M0-M5 小里程碑开发；每个里程碑必须通过自动测试和人工验收，再进入下一阶段。

## 1. 总体顺序

```text
M0 工程骨架
 -> M1 数据中心
 -> M2 轻量 CRM
 -> M3 销售工作台 + 销售BI
 -> M4 经营/财务BI + 风险
 -> M5 API/AI增强
```

精斗云 API 和 AI 都不是阻塞 V1 核心上线的前置条件。

## 2. M0：工程骨架

### 范围

- Git 项目结构；
- Next.js 前端；
- FastAPI 后端；
- PostgreSQL；
- Alembic；
- Docker Compose；
- 用户登录/退出；
- 主角色与数据范围基础模型；
- 基础布局和导航；
- 健康检查 `/health`；
- 日志；
- 单元/集成/E2E 测试框架；
- `.env.example`；
- 初始管理员创建方式。

### 退出条件

- 一条命令可在开发机启动；
- 空库可 migration 到最新；
- 能登录 5 种角色测试账号；
- sales 不能访问 owner-only API；
- Docker 重建容器后数据库仍在；
- CI/本地测试全绿。

## 3. M1：数据中心

### 范围

- data_source；
- import_batch；
- 文件持久化；
- Excel/xlsx/csv 上传；
- 销售导出识别；
- 订单头/订单行拆分；
- 合计行过滤；
- 客户/商品/销售标准化；
- 重复文件检测；
- 幂等 Upsert；
- 导入预检和错误提示；
- 导入历史；
- BI 基础销售聚合；
- 财务利润表/资产负债表基础月度导入。

### 测试必须覆盖

- 同一销售文件导入两次，销售额不翻倍；
- 一单多商品正确拆分；
- 修改后的订单再次导入执行更新；
- 合计行不进入销售明细；
- 无关键字段文件被拒绝且原因可读；
- 财务月度同月份再次导入按版本/确认规则处理。

### 退出条件

老板可以在测试页面看到从真实/脱敏样本导入后的销售月度汇总，且与源文件人工核对一致。

## 4. M2：轻量 CRM

### 范围

- 客户列表和客户 360；
- 潜在客户创建；
- 精斗云正式客户绑定；
- 客户负责人；
- 客户标签；
- 多联系人/关系角色；
- 客户备注；
- 跟进记录；
- 跟进方式/结果/资料发送；
- 下一步动作；
- 今日/本周/逾期待办；
- 商机；
- 客户转交历史；
- 公海（基础版）；
- 活动日志；
- 手机响应式关键页面。

### 退出条件

销售可完成完整链路：

`打开工作台 -> 找客户 -> 记录跟进 -> 设置下次待办 -> 创建/更新商机 -> 次日看到待办`

经理能看到团队数据但销售不能串看他人私有客户。

## 5. M3：销售工作台 + 销售 BI

### 范围

- 月销售目标配置；
- 个人目标完成率；
- 时间进度；
- 目标进度差；
- 剩余目标和日均所需；
- 节奏预测；
- 商机加权预测；
- CRM 登录活跃和有效活跃；
- 销售分析；
- 客户分析；
- 商品分析；
- 业务员分析；
- 销售变化贡献拆解；
- 客户沉睡/疑似流失/同期未复购提醒。

### 退出条件

老板能回答：

- 本月卖了多少、环比如何；
- 为什么涨/跌，主要是哪些客户/商品/业务员；
- 每个业务员目标完成到哪；
- 谁只是登录、谁产生了有效跟进；
- 哪些客户需要关注；
- 下月/本月商机储备如何。

## 6. M4：经营/财务 BI + 风险

### 前置

需要采购、库存、应收/收付款等源数据字段得到验证；未验证模块可隐藏，不允许用猜测字段做“假完成”。

### 范围

- 采购分析；
- 供应商分析；
- 库存分析；
- 财务月报；
- 经营销售额 vs 财务营业收入勾稽；
- 现金/月末资产负债变化；
- 应收风险（有可靠明细后）；
- 风险中心；
- 异常规则后台参数化。

### 退出条件

老板首页形成真正的“经营 + 财务 + 过程”统一驾驶舱，不混淆经营销售和会计收入。

## 7. M5：精斗云 API / AI 增强

### 7.1 精斗云 API

- 按届时官方文档实现认证；
- 测试连接；
- 增量同步；
- 指定日期重拉；
- 同步日志；
- API 数据进入与 Excel 同一标准化路径；
- 保留 Excel 应急导入。

### 7.2 AI

- Provider 配置；
- 月度经营总结；
- 客户摘要；
- 指标异常解释；
- 权限过滤后的自然语言问答（可作为后续子版本）。

### 退出条件

关闭 AI 或断开 API 时，CRM/BI 核心仍可运行。

## 8. Codex 每个任务的循环

每个独立任务执行：

1. 阅读相关文档；
2. 写 5~15 行简短计划；
3. 实现最小完整功能；
4. 新增/更新测试；
5. 运行相关测试；
6. 自检权限、数据迁移、兼容性；
7. 修复失败；
8. 运行本里程碑全量测试；
9. 更新 `CHANGELOG.md` / 任务状态；
10. 输出本次改动、测试结果和遗留事项。

禁止“代码写完但测试以后再补”。这个“以后”通常与办公室里的备用充电线住在同一个神秘空间。
