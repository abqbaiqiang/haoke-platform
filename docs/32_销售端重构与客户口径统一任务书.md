## 2. 冲突根源与下线项

系统原同时存在三套"客户状态"，为"新客户/有需求/报价/沉睡/成交"来回打架的根源：

| 体系 | 字段 | 取值 | 处置 |
|---|---|---|---|
| ① 客户阶段 | `customer.customer_status` | potential/contacted/demand/quoted/won/dormant | **下线**（迁移 0012 删列；表单去掉选择器；`quotation_sent→quoted` 自动改写逻辑删除；销售可改白名单同步收缩） |
| ② 合作状态 | `customer.lifecycle_status` | prospect/active/dormant/lost | 保留为唯一客户级状态；**沉睡改为按参数自动判定**，不再手动选 |
| ③ 项目阶段 | `crm_opportunity.stage` | 接触客户/推荐产品/选品/招投标/大单议价/交付/成交/流失 | 保留（docs/31 第 2.A 节已定稿），是流程推进的唯一正式定义 |

下线①的迁移影响说明（高风险变更，提前声明）：
- 删列 `customer.customer_status`，存量值不迁移不保留（测试数据，老板授权清除）；
- `crm_schemas` CustomerInput/CustomerView 移除该字段；`crm_service` 移除发报价自动改写（原 416–433 行）与销售可改字段白名单中的 `customer_status`；
- 前端 `labels.ts` 删除 `customerStatusLabels`；凡引用该字段的列表/筛选/测试同步改造；
- 客户页"客户阶段"筛选器一并移除，由新标签页取代。

## 3. 统一口径（唯一标准，全站执行）

### 3.1 四个维度各管一件事

1. **项目阶段**（推进到哪了）= 第 2 节③的 8 值，不动。
2. **合作状态**（客户现在什么状况）= 潜客/活跃/沉睡/流失；沉睡 = 有历史成交且距最近成交 > `dormant_days`（默认 90，BI 设置可调）；流失仅手动认定；疑似流失（≥`lost_warning_days`，默认 180）只是预警，不等于流失。
3. **客户等级 A/B/C/D**（价值分层）= 手动维护，与状态无关。
4. **客户标签**（特征备注）= 现有标签体系，不冲突。

### 3.2 客户页标签页（互斥级联，命中即停，数量加总 = 全部）

| 标签页 | 推导规则 |
|---|---|
| 沉睡客户 | 有历史成交，距最近成交 > dormant_days |
| 成交客户 | 有历史成交（精斗云销售单为准），且未沉睡 |
| 报价中 | 无成交，有开放项目且最高阶段 ∈ {招投标, 大单议价} |
| 意向客户 | 无成交，有开放项目（阶段 ∈ {接触客户, 推荐产品, 选品, 交付}） |
| 新客户 | 无成交，无开放项目（潜客） |
| （流失） | 手动认定流失：不入任何标签页，仅在"全部"可见、灰色标识 |

### 3.3 一词一义（术语锁）

- **成交** = 有精斗云销售单（铁律 2：精斗云为准）。项目阶段"成交"仅代表项目结项，不作为客户成交依据。
- **报价** 双轨且互不混用：业绩**漏斗"报价客户数"** = 当月报价动作留痕（`quotation_sent`，即 CRM_QUOTED_CUSTOMERS 现行口径）；客户页标签**"报价中"** = 项目阶段（招投标/大单议价）。界面文案需能区分语境。
- **沉睡** = 计算口径（dormant_days 参数）。标签页、重点提醒、业绩页用同一个数。
- **流失** 三个身份固定命名：客户流失（手动）/ 项目流失（阶段）/ 疑似流失（计算预警）。
- **新客户数**（业绩页/漏斗）= 本月新建档（CRM_NEW_CUSTOMERS）；**新增成交客户**（CUS_NEW_TRANSACT，首次成交）仅 BI 场景使用原名，不混叫。

### 3.4 重点客户 = RFM 重要层

工作台"重点客户"指标卡 = 本人可见客户中 RFM 分层以"重要"开头（M 高：重要价值/重要保持/重要发展/重要挽留）的客户数。RFM 仅覆盖有源销售记录的客户，纯潜客天然不计入。入口点击后进入对应客户列表（沿用"重点提醒点击直达筛选"交互）。

### 3.5 业绩漏斗（客户数口径）

新增客户 → 有效沟通 → 报价 → 成交，四格均为**去重客户数**：
1. 本月新建档客户数（CRM_NEW_CUSTOMERS）；
2. 当月被有效跟进的去重客户数（CRM_FOLLOWUP_CUSTOMERS）；
3. 当月报价客户数（CRM_QUOTED_CUSTOMERS，quotation_sent 留痕）；
4. 当月成交客户数（CRM_DEAL_CUSTOMERS，销售核实后给出，未核实不显示不补零）。

客户质量四指标：新增客户数（CRM_NEW_CUSTOMERS）/ 活跃客户数（CUS_ACTIVE）/ 沉睡客户数（CUS_DORMANT）/ 复购客户数（CUS_RETURNING）。

## 4. 实施阶段计划

按需求文档第八节顺序，结合拍板调整。**实施进度（2026-09-18）：阶段①–⑤已完成并独立提交（销售端六页全部对齐参考图与本口径；每阶段全量回归 + 销售端 E2E 桌面/移动通过）；阶段⑥待销售端、管理端全部定稿后执行。迁移编号实际落地为 0012=跟进附件表、0013=客户口径（下线 customer_status + company_address），与下文按阶段预编号的差异以此为准。**

### 阶段① 统一 Layout（销售端）
- 销售端四页（工作台/客户/待办/业绩）套用 globals.css 既有 Design Tokens 与公共类（page-head/kpi-card/panel-card/table-dense/status-tag/empty-hint），控件高度、间距、状态色不新增私有值。
- 顶部栏统一：全局搜索、日期、通知、当前用户。
- 不改路由与权限。

### 阶段② 工作台（首页）
- 4 指标卡：本月目标（目标/完成/比例）、今日待办、待跟进项目（全员开放项目数）、重点客户（RFM 重要层，点击直达筛选列表）。
- **项目面板**（本阶段核心新增）：列表列 = 同事姓名/项目名称/客户/当前阶段(进度)/产品提报/预计金额/下一步动作/预计成交时间；默认展示开放项目，按预计成交时间排序。
  - 后端新增销售端全员项目读接口（复用管理端项目管理查询，销售角色放开读权限）；**他人项目只读**，仅本人项目可编辑——权限测试按 AGENTS 第 6 节写越权用例（S1 改 S2 项目必须 403/404）。
- 今日作战区：按参考图（客户/事项/当前阶段/截止时间/去跟进+完成）。
- 重点提醒：每条（沉睡/疑似流失/停滞项目/逾期任务）点击**直达对应筛选后的客户/任务列表**，"查看全部"进问题客户汇总页。
- 快速记录跟进：文字 + **图片粘贴**（clipboard 粘贴生成附件，无文件选择按钮）；新增跟进附件表（增量迁移 0013），跟进详情/客户 360 历史展示图片。
- 最近跟进模块动态位置：今日待办 ≥ 阈值时下移（CSS order），少则上移。
- 全站文案"商机"→"项目"已在第 1 期完成，参考图中的"待跟进商机"卡落地时用"项目"。

### 阶段③ 客户管理
- 标签页改为第 3.2 节级联推导（后端计算返回各页 count + 列表，前端不做本地推导）。
- 迁移 0012：下线 customer_status（第 2 节）。
- 迁移：customer 增 `company_address` 列（可空），客户详情"公司信息"卡展示与编辑；列表不展列。
- 客户详情保持现有 360 结构，补：地址、开放项目（阶段推进）。

### 阶段④ 待办（三栏看板）
- 顶部统计卡（今日应完成/已完成/已逾期/本周新增）+ 三栏（今天必须完成/已逾期/未来计划），每卡含客户/事项/时间与"去跟进/完成/设为今天"操作。
- **空列收纳**：已逾期清空后该栏收起，其余两栏等分放大（flex 变宽，不留空壳）。
- 不做日历视图（老板拍板，需求文档第五节日历方案作废）；客户周期提醒（去年春节采购类）作为独立后端任务另行立项，不阻塞本阶段。

### 阶段⑤ 我的业绩
- 顶部：本月目标/完成/差距/剩余工作日/日均需完成（现有口径不动）。
- 销售漏斗：第 3.5 节四格客户数 + 转化率。
- 客户质量四指标卡（第 3.5 节），替换参考图中缺沉睡/活跃的"客户结构"组合。
- TOP5 客户/商品：仅本人（现行 self scope，接口已满足）。
- 需要关注（沉睡/疑似流失）沿用计算口径，点击直达筛选列表。

### 阶段⑥ 全站 UI 一致性审计
- 待销售端、管理端全部定稿后，按 AGENTS 12.5 执行最终 FULL UI CONSISTENCY AUDIT。
