## 4. 解析、精度与幂等

- 按内容签名识别 BIFF/OLE xls 和 ZIP/OOXML xlsx，限制压缩展开大小、行列数和解析资源；不执行宏或公式。CSV 编码及分隔符可明确选择，错误导出防公式注入。
- 支持标题、日期说明、真正表头、订单首行、续行、合计、空白边界及空工作表。销售商品编码列有 `合计:`，采购对应列有 `合计`；不能只检查第一列。
- 合计仅做勾稽依据，不算业务行。继承仅限已验证订单块的头字段，遇到边界重置；未知行或孤立明细明确报错。
- 金额 Decimal/NUMERIC，数量/单价保留规定精度；空值与零值分开。逐单校验头金额、明细和合计，容差规则明确记录，超差不静默成功。
- 样本中同一订单可以有重复商品甚至相同内容的两条明细。不能按商品编码或整行哈希消除业务行。
- 订单内 line_no 按已解析明细顺序生成。当前文件没有稳定源明细 ID；订单完整块通过核对后才允许更新整套当前明细。旧版本及移除明细保留审计，不无痕物理删除。
- 重导去重分三层：相同文件 SHA256、来源＋单号、订单＋line_no；不同账套需明确数据源隔离，不能无声合并编码。
- 变更文件、明细增删/重排、旧文件重导都要单独验证。不能因本次文件未包含某订单就推断其已删除。
- 同时导入同一批次/订单需事务和唯一约束；失败不能产生半张订单、重复聚合或悬空批次。重新计算影响日期的聚合，不累加旧值。
- 原文件、原始行号、来源键、解析/映射版本、每次批次与订单版本必须可追溯。错误列表不把整行敏感信息写入日志。

## 5. 权限

遵循 docs/05 矩阵，不因数据导入给管理账号全部业务数据权限：

- admin：数据源与导入操作、受控运维诊断；业务经营汇总仍按显式授权。
- owner：导入信息只读、全局业务核对；矩阵未赋予的上传/确认权限不擅自增加。
- finance：财务模板导入；经营数据按授权范围读取。
- manager/sales：不开放数据导入操作；业务读取分别限团队/本人。
- 文件下载、错误行详情、导入预览与最终数据接口全部由后端校验，成本字段单独控制。猜测文件路径或批次 ID 不得绕过权限。
- 无人员映射的数据不向普通销售默认开放；历史订单人员与客户当前负责人分开保存，不用猜测归属修补权限。

## 8. 8 月财务报表样本补充

本节记录先前只读验证和映射依据；现在已实现并通过人工夹具和真实样本隔离测试。本地真实财务预检等待用户空白策略确认。实际金额、源文件哈希及单元格证据保存在 `app-data/sample-review-20260908/8月财务报表检查报告.md` 与 `finance_profile.json`，不提交到 Git。

### 8.1 期间、单位及结构

- 两份报表内部编制单位一致、单位为元。正式导入仍须绑定正确账套，不能只凭文件名判断主体或期间。
- 利润表 B2 为 `2026年8期`，正式表头 A3:D3，行次 B4:B35。C 列是本年累计，D 列是本月；E:F 为辅助公式/附注。不能误把累计当本月，也不能把附注管理费再次计入正式费用。
- 资产负债表 E2 为 `2026-08-31`，A:D 为资产、E:H 为负债及权益。左右都包含独立行次，按报表类型＋行次＋科目名称校验，不能丢弃右半表或把不同区域同一物理行当同一科目。
- 资产 C/G 为期末、D/H 为年初。`begin_value` 必须同时保留原标签“年初余额”，不得解释为上月余额。7 月报表缺失时相关环比不可计算。
- 期间规范化为当月 1 日，期末日期与原表日期保留追溯。附注出现别的月份不改变正式报表期间。

### 8.2 财务字段映射候选

每项均需验证科目标签及行次，位置变化时重新识别/映射；不硬编码工作表的完整月份名称。

| 源项目（本模板位置） | 标准事实 | 值域 |
|---|---|---|
| 利润表营业收入，第 4 行 | revenue | D → period_value，C → ytd_value |
| 营业成本，第 5 行 | cost（与指标 FIN_COST 对应） | 同上 |
| 销售费用/管理费用/财务费用，第 14/17/21 行 | 相应费用科目代码按映射表冻结 | 同上，负数保留 |
| 净利润，第 35 行 | net_profit | D → period_value，C → ytd_value |
| 资产表货币资金/应收账款/存货，第 5/8/13 行 | cash / ar / inventory | C → end_value，D → begin_value（年初） |
| 资产表流动资产/资产总计，第 19/35 行 | 相应标准科目代码按映射表冻结 | 同上 |
| 资产表流动负债/负债合计/权益合计，第 15/22/34 行右侧 | 相应标准科目代码按映射表冻结 | G → end_value，H → begin_value（年初） |

`metric_code` 为财务事实科目代码，EXEC_/FIN_ 为指标字典代码，建立明确映射，不混为同一命名空间。其余科目保留 RAW，按模板逐一映射，不把小计、总计和“其中”子项重复求和。

### 8.3 空白、公式及确认规则

- 源空白保留 null；明确零保留 Decimal(0)。样本若按空白零贡献可勾稽，仅证明该假设下的算术关系，不证明所有空白均是业务零。
- 预检应显示空白科目及模板的空白策略。必需科目未找到/金额不可用必须报错，不能静默补零后标成功。策略与模板版本一同追溯。
- 正式财务金额列当前是数值/空白；辅助 F 列公式有缓存。本次以 Decimal 独立计算验证了缓存。未来不能只用 `data_only` 将缺缓存公式误读为空白零，也不任意执行上传公式/宏。
- 保留源公式及缓存状态作追溯；公式落在必需源金额且无可信结果时，预检报“公式结果不可用”，不能算作成功。
- 负费用及负余额保留符号并提示；附注可辅助解释，但不能视为凭证核验。
- 财务确认状态与导入技术成功分开。文件中有月末日期、算术通过都不意味着已结账。
- 相同文件重传不增加有效事实；同主体/月份/报表类型的新版本保留旧批次，仅显式确认后切换当前有效版本。已确认月份的替换需解除确认/重新确认的受控流程和审计，不静默覆盖。
- 不将单张报表内部平衡称为会计审计通过。经营销售与财务收入的差额仅展示对照，不自动调账或互相覆盖。

### 8.4 新增验收场景

- 本月与累计列颠倒、资产左右两区、年初误当上月、科目行次为文本、合并标题、辅助明细重复计入。
- 缺关键科目、空白/零/负数、单位及期间/主体冲突、缺缓存公式、科目标签或行次重复。
- 期末/年初资产负债平衡、利润三层勾稽、存货及费用“其中”子项不重复加总、管理费附注只作核对。
- 同文件重导、同月份新版本切换与旧版追溯、已确认期间替换权限、财务角色与 admin/owner 操作边界。
- 只有 8 月表时隐藏无依据的 7 月环比；补齐连续月报后验证累计衔接及资产余额月变动。不同财务版本不自动串接。

样本检查与功能验收是两类证据；本次功能测试结果见 M1 验收报告。人工构造夹具用于可提交测试，真实数据仅用于私有对照验收和本地核对。
