## 1. UI 总策略（老板问的"边做边调还是回头统一"）

**结论：基线先行 → 边做边按基线执行 → 最后收口审计。不做回头统一大改。**

- **第 0 期先把设计基线定死并写成代码**（globals.css 设计令牌 + 公共样式类 + 验收清单），此后每一期的页面都"按基线一次做对"——这样不存在"先凑合、回头再统一改"的二次返工。
- 收口的全局一致性审计（AGENTS §12.5）只处理零散不一致，不是第二轮重构。
- **色彩决定（已拍板口径）**：**保留现有色值基线**（深色导航 #1e2a38、品牌蓝 #2563eb、浅灰背景、白卡细边框），不采纳规范里的 #172332/#2F6FED 新色值——两者是同一风格，换色收益趋零、全站回归风险大。规范中真正要采纳的是**规则**：首屏 KPI ≤6、黄/红仅用于异常、数字右对齐千分位、表格行高 44–48px、口径说明收进 ⓘ、空态给"为什么为空+下一步"。
- 设计规范 docx 第 5 节的"AI 效果图提示词"可在每期动手前先生成效果图给老板确认视觉，确认后再写代码。

## 2. 现状基线（新会话不必重新调研）

**已存在、不要重做的**：
- 客户详情工作台（2026-09-16 完成，结构=规范 §3.9）：概览 KPI、下一步行动、当前商机、最近跟进/交易、联系人、时间线 Tab。
- 驾驶舱基线（2026-09-14"晨会大屏"）：核心金额→KPI+目标→趋势→折叠明细，零值区不渲染。本期只**增量补模块**。
- 销售分析能力：口径/维度切换、TopN、明细下钻弹窗（bi.tsx setDrill/Orders）、月度分页。
- 客户分析（customer-analytics.tsx）：RFM 八层（阈值可配）、复购率趋势、转化周期分桶、TOP20、客单价。
- 商品毛利（2026-09-17）：/api/bi/product-margins + 销售分析页区块。
- 批量能力：批量分配/认养/标签管理（CRM 内）。
- 团队执行表（bi.tsx team tab）、重点关注（attention tab，/api/bi/attention）。

**真实数据规模**（决定功能取舍）：3 名销售（肖昌兴/夏方鹏/李延伟，后者兼老板角色）+ demo 账号；9 个月真实销售 4.2M；商机记录极少（录入刚起步）；财务仅 2026-08 已确认。**凡是为"大组织"准备的模块一律暂缓**（公司目标树、部门管理、批量人员权限）。

## 3. 分期计划

### 第 0 期：设计基线（约 1 天，P0）
目标：后续所有页面"按基线一次做对"的依据。
1. globals.css 增补/核对令牌：间距体系（4/8/12/16/24）、卡片圆角与边框、表格行高 44–48px、状态色（成功 #15803d/预警 #b45309/风险 #b91c1c——沿用现有语义色微调）、字号阶梯（24/16/14/12、KPI 28–36）。已有令牌不重命名、不换值，仅补缺。
2. 公共样式类最小集：页面头（标题+说明+右侧动作）、筛选条（一行紧凑）、KPI 卡（主值+对比+状态）、区块卡、高密度表、状态标签、空态（"为什么为空+下一步"）。以 CSS 类 + 现有组件形态落地，不引入新 UI 框架。
3. 产出《页面验收清单》（规范 §7 的 12 条裁剪为可执行版）写入本文档附录，作为每期验收依据。
4. **产出设计令牌对照表**（规范 §6.1 → 现有 globals.css 变量名），标注"采纳规则、保留现值"的映射。
验收：老板确认基线效果图（可先用规范 §5 提示词生成驾驶舱效果图）。不改任何业务逻辑与 E2E 选择器。

### 第 1 期：信息架构收敛 + 商机升级 + 驾驶舱增强（约 2–3 天，P0）
1. **导航 4 组收敛**：经营中心（驾驶舱/销售分析/客户分析/团队执行）、客户经营（客户管理/公海/商机/待办）、管理后台（数据中心/人员/目标与日历/CRM 配置）、系统（我的账号/系统状态）。老板默认首页=驾驶舱（现有 home 视图增强）。合并"日历与分析设置"入"目标与日历"。改 page.tsx 导航分组与文案。
2. **删除 bi.tsx"分析导航"顶部标签**（与左侧重复的全局二级导航）；各分析页保留自己的下钻与子视图。**E2E 同步**：bi.spec/cockpit.spec 的导航引用改为新入口；sales/attention/customers 的数据源选择保留在页面筛选条。
3. **商机管理升级**（crm.tsx 商机 tab 重构为独立区块）：
   - 顶部 5 指标：有效商机金额、加权金额、本月预计成交、停滞商机数、新增商机。
   - 列表强化：客户/阶段/预计金额/加权金额/预计成交日/负责人/下一步（next_promotion）/最后推进/停滞天数。
   - 停滞判定：商机无下一步任务且超过 N 天未更新即标黄（7 天）/标红（14 天），阈值入 CRM 设置（可配置，存 crm_setting JSON，避免 migration——若需新字段则走 Alembic）。
   - "没有下一步不能算健康商机"：新增/编辑商机时 next_promotion 或关联待办至少其一必填（后端校验 + 提示）。
   - 看板视图（按阶段分列拖拽改阶段）**列为本期可选**，工作量超出时降级到第 2 期。
4. **驾驶舱增量补两模块**：商机管道（5 指标+阶段漏斗，数据源 OPP_* 已有）；"需要关注"（逾期任务/沉睡重点客户/停滞商机/目标偏差，按影响金额排序，每条含对象+原因+建议动作+入口，数据复用 attention/团队 API）。
验收：老板 30 秒内从驾驶舱看到销售/目标/趋势/异常/商机管道；从异常到动作 ≤3 次点击；全量回归+E2E 绿。

### 第 2 期：分析增强（约 2 天，P1）
1. 销售分析新增**增长/下降贡献**（本期 vs 上期，按客户/商品列增减金额 TopN——新后端聚合，口径挂本期/上期已导入数据）。
2. 客户分析新增：风险客户列表（90/180 天未成交，按历史贡献排序，点击直达客户 360）、增长客户列表、集中度卡（Top5/Top20 占比、最大客户占比）。
3. 驾驶舱"数据健康"模块：最近导入时间、待映射订单/客户数（含影响金额）、待财务确认期、异常记录数。正常时弱化。
4. 报表导出 CSV（明细表通用导出，若老板确认需要）。
验收：老板能回答"销售变化是谁造成的""哪些客户在流失""数据哪里没就绪"。

### 第 3 期：CRM 与管理页密度治理（约 2 天，P1）
1. 客户管理/公海：顶部紧凑筛选条 + 智能视图预设（我的重点客户/30 天未联系/近 90 天未成交/有商机/新客户/沉睡）；表格列强化（最近联系、下一步、近 90 天销售、商机数）；导入说明降级为右上角按钮。
2. 待办行式列表（管理端对齐销售端密度，一屏 8–12 条）。
3. 数据中心健康化：顶部 5 状态卡 + Tab（导入历史/映射/财务确认/数据质量）。
4. 标签管理表格化（名称/分组/状态/使用数/操作，支持搜索）。
验收：列表信息密度达标（一屏可见条数）、批量动作可达。

### 暂缓清单（明确不做，避免范围蠕变）
换色值；公司目标树；部门/团队组织管理；全局搜索 Ctrl+K；我的账号重构；看板拖拽（若第 1 期未做）；真实路由 /dashboard 等（**保持现有 hash 单页结构**，仅重组导航分组——改真实路由是架构级变更，单独立项）。

## 4. 执行纪律（每期必须）

1. 每期开工前：读 AGENTS.md + TASK_STATUS + 本文档；输出该期简短实施计划。
2. 每小步：全量回归（run_tests.py）+ 受影响 E2E 同步修改 + 独立提交（可回滚）。
3. 每期收尾：对照附录验收清单逐项勾选；更新 CHANGELOG/TASK_STATUS/MANIFEST；老板截图验收。
4. 销售员端（sales.tsx/sales/*）**不受本期影响**，双端独立布局、共享令牌。
5. 口径披露不消失：未核实/源单据口径提示收进 ⓘ 可查，但驾驶舱与报表必须保留一处可见入口。
6. 已知偶发：pytest test_opportunity_products_roundtrip_and_recent_list 全量偶发、单跑必过；E2E 需本地栈。
