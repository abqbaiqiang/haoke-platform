# 总体检查与 UI 改版建议

> 更新：本报告保留 2026-09-12 的审查基线。用户已批准并实施修复，当前状态以 20_驾驶舱改版与问题修复验收.md 为准。

日期：2026-09-12。范围：当前工作区（包含他人尚未提交的修改）及最近经营首页、账号简化、客户分析改动。

## 结论

工程基础可以继续使用；现有自动测试覆盖了登录、后端权限、导入幂等、审计和迁移等关键基础。但新增客户分析存在已复现的指标错误，UI 存在真实的可读性与手机布局问题，当前版本不应认定为全部验收通过。

本次为审查：没有修改业务实现、指标字典或数据库结构。新增复现脚本与截图保存在本地忽略目录 `.tools/qa/`。下列问题尚未修复，文档中的历史“完成”记录不能替代本次复核结果。

## 一、优先修复的问题

### 1. P1：真实绑定流程产生的潜客未计入成交转化

- 位置：`apps/backend/app/bi_service.py:604-605`；对应正常绑定流程在 `crm_service.py:193-200`。
- 绑定正式客户后，原 CRM 潜客被设为 `is_active=False`，过程记录迁移到正式客户；转化统计却要求原潜客 `is_active=True`。
- 用真实绑定 API 构造“8 月 30 日创建潜客、9 月 3 日首次成交”的样本，接口返回统计样本 **0**，应为 **1**、转化周期 **4 天**。
- 当前新增测试直接设置 `bound_customer_id` 并保留活动状态，绕过了实际业务流程，因此没有发现这个问题。正式客户画像也没有反查历史潜客，正常绑定后转化周期无法正常呈现。
- 修改建议：以有效绑定关系追溯原始潜客创建日期，按当前授权范围查询正式客户及有效销售；同时排除作废、退货、未来订单，按选定数据源统计。补真实创建/绑定链路及转交后的权限测试。

### 2. P1：客户分析销售金额、客单价没有扣减已确认退货

- 位置：`apps/backend/app/bi_service.py:535-541`。
- 已核实状态下先用 `normal_sale` 排除退货，再累计普通订单金额；这与经营销售额的退货扣减规则，以及 `SALE_AOV = 经营销售额 / 销售订单数` 不一致。
- 固定样本：9 月普通销售 **1,000.30 元 / 4 单**，另有已确认退货 **50.00 元**。客户分析仍显示 **1,000.30 元**，应为 **950.30 元**；其客单价也会随之偏高（250.08，而应为 237.58）。
- 修改建议：金额共用既有 `order_value` 规则；有效订单数、复购次数、最近有效成交日期分别按各自口径统计，不能通过一份过滤后的订单列表处理所有指标。

### 3. P1：调整 RFM 频次阈值会改写固定复购率公式

- 位置：`apps/backend/app/bi_service.py:564,581`。
- 指标字典的 `CUS_PERIOD_REPEAT` 固定为“统计期内至少成交 2 张有效销售单”；实现却使用可配置的 `rfm_freq_orders`。
- 同一份订单，将 RFM 高频门槛从 2 改成 4，9 月复购率从 **33.33%** 变为 **0.00%**，没有新增或修改交易。
- 修改建议：复购判定固定为两单；RFM 分层使用独立参数。累计复购与月度复购应明确标明不同统计期间，避免共用月/季指标却显示累计值。

### 4. P2：老板账号缺少日常配置入口，RFM 参数没有页面控件

- 位置：`apps/frontend/app/bi.tsx:147`；`apps/frontend/app/crm.tsx:90`；`bi.tsx` 的 `Settings` / `Configuration`。
- 现有使用决策为老板负责日常配置，但“日历与分析设置”和“CRM 设置”标签仅对 `admin` 展示。老板实际登录后无法从这些页面确认销售口径或维护参数。
- 客户分析提示“老板在日历与分析设置中调整 RFM 阈值”，但该表单和前端类型没有新增 RFM 参数字段。后端 API 可配置不能替代用户可操作的配置页面。
- 修改建议：在老板的统一“设置”入口开放已有授权能力，补字段、校验及保存反馈，并做老板账号浏览器验收。后台权限范围保持不变。

### 5. P2：客户分析手机页面宽度超过屏幕一倍

- 位置：`apps/frontend/app/customer-analytics.tsx:84`；`apps/frontend/app/bi.tsx:148`。
- 实测 **390 × 844** 视口，文档宽度为 **819 px**；图表区域两列约为 **472 px + 315 px**。
- 固定内联 `gridTemplateColumns: "3fr 2fr"` 覆盖手机单列规则；整个分析页又嵌套在筛选工具栏中，内容的最小宽度继续撑大布局。数据源选择器落在整页报表之后。
- 修改建议：分析正文与筛选栏分离；移动端图表单列；栅格子项允许收缩；宽表格只在自身容器横向滚动。验收覆盖 390、768、1440 px，并断言整页不横向溢出。

### 6. P2：侧栏主题污染正文分析标签，可读性很差

- 位置：`apps/frontend/app/globals.css:143-144`。
- `.dash-root nav button` 同时命中深绿色侧栏和浅色正文中的 `.bi-tabs`。正文未选中文字为浅绿，选中文字为白色，接近背景色。
- 实际客户分析截图已确认；用户难以分辨“销售分析、客户关注、客户分析”等入口。
- 修改建议：侧栏主题限定到侧栏导航，分析标签单独定义文字和选中状态；按实际渲染检查对比度、焦点和触屏点击区域。

### 7. P2：验收记录与当前检查结果不一致

- `scripts/run_tests.py` 在 Ruff 阶段被 `tests/test_m5_customer_analytics.py:145` 的 E731 阻止；当前不能声称完整检查全绿。
- CRM 浏览器用例仍查找“客户与待办”导航按钮，当前导航已改为“客户管理”，需要同步可访问名称或使用稳定的导航定位。
- 修改建议：修复规范错误与失效用例，再补上述真实业务回归；测试报告分别列出现有用例、新增回归、浏览器和部署检查结果。

## 二、UI 为什么难用，以及如何改

### 现状观察

1. **首页视觉重心失衡。** 大面积渐变问候横幅和连续警告条占据首屏；1440 px 桌面下六张指标卡呈“5+1”排列，最后一张独占第二行，大量留白。卡片内图标、数值、口径入口并排竞争，标签和“口径”出现不自然折行。
2. **未就绪数据占据了主要位置。** 多张财务卡显示破折号、同样的未导入提示又在下方重复出现。应在标题旁保留明确数据状态，并将尚不可用的财务模块汇总为一个可展开区域；不能以假零值填充。
3. **客户列表缺少经营信息且效率低。** 一个客户占约 150 px 高度，桌面首屏只能完整看到约 3 个客户。名称、编码和“查看客户”占据整块区域，最近跟进、下一待办等关键信息没有并排呈现。
4. **功能入口与任务不对应。** 客户分析藏在销售工作台内；客户、待办、跟进、商机挤在同一页面。老板和同事登录后都先到平台首页，同事还要寻找自己的工作入口。
5. **页面缺少明确导航状态。** 顶层和子页面主要使用 React 内存状态切换，刷新会回首页，无法直接分享客户详情地址，浏览器返回不能按业务页面逐步回退。
6. **图表占位多，行动入口少。** 本次样本的客户等级结构全部为未分级，环形图信息量有限；客户排名没有直接进入客户详情的操作。应优先展示可解释、可下钻的内容。

### 建议的改版方向

用户已明确选择 **数据驾驶舱风格**。老板首页以经营指标和图表为核心：紧凑摘要、主趋势图、客户贡献、团队目标及待处理事项同时可见；统一色彩语义、图表比例和信息密度。保留经营/财务不同口径、期间与数据状态；不使用装饰性大横幅或无数据的虚假图表填充版面。同事端保留以待办和客户跟进为主的工作入口。

| 区域 | 推荐调整 | 目的 |
|---|---|---|
| 全局框架 | 紧凑侧栏、清晰分组、统一标题与操作栏；中性浅底，深绿作为强调色；使用统一线性图标 | 降低装饰干扰，建立层次 |
| 老板首页 | 数据驾驶舱：顶部核心指标；中部主趋势图与目标进度；下部客户贡献、团队执行与关注事项；财务按可用期间明确展示 | 首屏回答业绩、变化、行动 |
| 同事首页 | 我的工作台：今天要跟进、逾期事项、近期客户、目标进度；突出记录跟进和完成待办 | 缩短每日操作路径 |
| 客户列表 | 桌面采用紧凑表格；名称、负责人、等级/标签、最近跟进、下次安排、操作；缺失数据如实显示 | 同屏比较更多客户 |
| 客户详情 | 顶部身份与主要操作，下面分资料/跟进/待办/商机/交易；轻编辑可用抽屉，详情保留独立地址 | 避免长页面和反复跳转 |
| 分析页面 | 筛选统一置顶；摘要、主要图表、明细分层；排名可下钻；口径和时间始终可查 | 保留可信度并提高阅读效率 |
| 系统设置 | 人员、数据、参数集中管理，按已有后端权限显示入口 | 老板能够完成日常维护 |
| 手机 | 简化导航、图表单列、客户使用紧凑卡片、常用操作便于触达 | 在手机上完成查客户和记跟进 |

建议按顺序推进：**修指标与入口错误 → 确定首页/客户列表/客户详情三页设计 → 统一组件和导航 → 扩展到其他页面 → 完整验收**。不在本轮扩展采购、库存、应收等尚无可靠数据的模块。

随本次检查提供对话内驾驶舱布局预览：经营摘要、可切换的销售/客户趋势、团队目标、客户贡献及关注事项。所有数字和客户名称均明确标记为示意数据；该预览用于讨论视觉方向，未接入真实 API，未替换现有页面，也不构成新功能上线。
