# 销售端信息架构与 UI 复盘（2026-09-14）

⚠️ DEGRADED: single-context (both independent sub-agents failed with usage-limit errors).

本次仅检查、复盘和提出方案，不修改业务代码、角色权限、客户归属或指标口径。目标为 apps/frontend/app/page.tsx 及其 CRM、BI 子页面。以当前代码、PRD、页面权限矩阵和本地 demo_sales 实际页面为依据；非真实员工访谈结果。登录会产生正常会话/登录审计记录，未提交任何客户操作。

## 结论

视觉骨架已有基础，但产品组织仍以模块为中心。销售员需要先在重复入口中选择，再从指标和长说明中寻找下一步操作。继续换色或堆设计 skill 无法保证改善。

### 已确认的优先问题

1. **P1：角色工作入口不清。** page.tsx:94–97 为销售展示 9 个入口，包括经营总览、销售分析、客户分析。登录默认进入客户列表，既不是待办工作台，也没有明确的今日任务。经营总览即便数据范围正确，其页面名称和职责仍与销售工作台重叠。这是信息架构问题，不据此认定越权。
2. **P1：工作台统计压过工作。** bi.tsx:49–50 将所有 metrics 等权渲染；bi.tsx:153 显示计数但没有今日客户清单。实际桌面 20 张指标卡加 4 张计数卡，包含登录工作日、活跃率、预测等；手机截图 390×3318，前段用于导航、筛选和技术说明。缺失值还分别占据整张卡片。建议今日客户/待办为主体，目标与完成额为摘要，详细过程统计退至个人业绩或管理分析。
3. **P2：同级导航重复、名称不一致。** page.tsx 的侧栏与 crm.tsx:163、bi.tsx:151 重复提供客户/公海/商机/分析入口；侧栏“待办与跟进”实际进入 tasks，跟进仍是另一 tab。CRM 内部 tab 使用局部 setTab，父级侧栏选中状态不会总是同步。建议一级导航只有一套，页内只切换当前业务的视图。
4. **P2：客户表不是行动清单。** crm.tsx:172 的主列为名称、编码、负责人、认养人、等级、操作，缺少最近跟进、下一次联系和下一步。实际“我的客户”重复显示本人负责人，不能帮助决定先联系谁。建议优先名称/联系人/最近跟进/下次联系/下一步/记录跟进；编码及归属详情按需展开，共同认养信息仍在需要协同时保留。
5. **P2：管理和技术语境占据日常界面。** bi.tsx:151 对销售展示查看人员、分析数据源、源销售核对/已确认口径；crm.tsx:173 对本人待办/商机展示负责人筛选。不是所有条件都有必要交给销售选择。保留数据待核实的真实状态，但用简短状态和详情说明承载；配置责任留在老板端。不得默认把未核实数据显示成已确认。

### 保留、合并、降级建议（待实施，不等于删除业务）

| 当前内容 | 建议 |
|---|---|
| 销售工作台 | 成为默认首页：今日/逾期客户与待办、快速跟进、小型业绩摘要 |
| 客户管理 | 改为“我的客户”，突出下一步动作 |
| 客户公海 | 保留认养入口，归入“客户”下的公海视图或次级入口 |
| 待办与跟进、我的待办、跟进记录 | 同一工作流程：未来动作是待办，已发生记录是跟进，避免入口混名 |
| 经营总览、销售分析、客户分析 | 销售侧汇聚为“我的业绩”；老板保留经营驾驶舱；客户提醒进工作台 |
| 商机管理 | 暂保留在客户详情；是否单独设主入口取决于销售是否实际维护报价、阶段和预计成交 |
| 登录/活跃、加权预测等大量指标 | 从销售首页降级；既有指标和后台计算不删除 |
| 我的账号 | 放到头像菜单等次级位置 |

候选一级导航：工作台、客户、待办、我的业绩。商机是否独立尚需业务使用情况，不擅自废弃。

## 反思与工具选择

此前把颜色统一、卡片美化、构建通过和截图无溢出当成主要验收证据，缺少销售角色逐项审视和任务闭环验证。老板的晨会驾驶舱方向被扩展成多角色共用目标；这是实施与验收方法的责任，不应归咎于用户没有说清楚。

PRODUCT.md 已写蓝色，DESIGN.md 内仍有浅侧栏/深侧栏、主按钮 ink/蓝色冲突；驾驶舱 surface brief 仍指定森林绿和 all roles。context 同时报告 PRODUCT schema 旧、buildPath 未设。按 skill 要求仅报告，本次不顺手改写设计契约。后续需分别建立销售与老板页面目标，再统一上下文；可用 init 更新产品记录，并明确先做交互原型还是先做视觉图。

- Impeccable：可保留做结构审查、精简与最终检查，但检测器没有业务理解能力。
- UI UX Pro Max：作者仓库提供配色、字体、图表、设计系统和 UX 规则，可作为视觉参考，不能据此声称一定比现有方案好。https://github.com/nextlevelbuilder/ui-ux-pro-max-skill
- Anthropic frontend-design：侧重鲜明视觉与前端实现；不解决本项目的角色功能取舍。https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md
- 更可靠的补充是熟悉 B 端 CRM 的产品/交互设计师：先交付角色功能图和可点击流程原型，再由开发实现。Figma 可以承载和评审原型，但工具本身不决定业务取舍。

下一步建议先做销售工作台、客户列表、记录跟进三个关联界面的可点击原型；用“找到今日客户→记录沟通→安排下次跟进”和“从公海认养→出现在我的客户”验收，再决定全面实施。涉及保存或认养的演练使用隔离测试数据。
