# 松茂经营管理平台 V1 测试与验收标准

**版本：** v0.1  
**原则：** “页面能打开”不等于完成。数据正确、权限正确、重复导入不炸、备份能恢复，才算完成。

## 1. 测试层级

### 单元测试

覆盖：

- 指标公式；
- 日期/同比环比边界；
- 状态映射；
- 客户沉睡/流失判断；
- 目标完成率/时间进度；
- 权限判断函数；
- Excel 行解析和订单头继承逻辑。

### 集成测试

覆盖：

- API + PostgreSQL；
- 数据导入 -> CORE -> BI；
- CRM 写入 -> activity_log；
- 用户角色和数据范围；
- migration。

### E2E

使用 Playwright 或等价成熟工具，覆盖关键用户流程。

## 2. M0 验收

- [ ] `docker compose up` 能启动全部核心服务；
- [ ] 新空数据库能执行 migration；
- [ ] owner/manager/sales/finance/admin 可登录；
- [ ] 错误密码拒绝登录；
- [ ] 停用账号拒绝登录；
- [ ] sales 访问 owner-only API 返回 403；
- [ ] 生产环境密钥不会出现在前端 bundle/log；
- [ ] PostgreSQL 不暴露公网端口配置。

## 3. 数据导入验收

### 销售文件

- [ ] 一张多商品销售单只产生 1 个 order + N 个 lines；
- [ ] 后续商品行正确继承订单头；
- [ ] “合计”行不入库；
- [ ] 同一文件重复导入，订单数/销售额不翻倍；
- [ ] 同一订单变更后重新导入能更新；
- [ ] 文件缺关键列时阻止正式导入；
- [ ] 错误行显示行号、字段和原因；
- [ ] 原始文件和 import_batch 可追溯；
- [ ] 导入成功后 BI 聚合刷新。

### 金额精度

测试样例：

- 0.1 + 0.2 等金额场景不出现二进制浮点尾差；
- 汇总与源文件允许的舍入差异必须有明确规则；
- 金额存储 NUMERIC。

## 4. CRM 验收

### 客户

- [ ] 销售可查看本人客户；
- [ ] 默认不可查看其他销售私有客户；
- [ ] 经理可查看团队客户；
- [ ] 老板可查看全部；
- [ ] 潜客可在没有精斗云编码时建立；
- [ ] 后续能与精斗云正式客户绑定；
- [ ] 客户转交保留历史。

### 联系人/标签

- [ ] 一个客户可有多个联系人；
- [ ] 联系人可标记老板/采购/财务等角色；
- [ ] 一个客户可有多个标签；
- [ ] 标签筛选结果正确。

### 跟进

- [ ] 可选择跟进方式、结果、资料发送状态；
- [ ] 可填写简短备注；
- [ ] 设置下一步后可生成待办；
- [ ] 跟进写 activity log；
- [ ] 普通销售不能无痕删除历史跟进。

### 待办

- [ ] 今天/本周/逾期视图正确；
- [ ] 完成后状态和完成时间正确；
- [ ] 经理分配给员工后员工可见；
- [ ] 非本人/非团队用户不能修改。

### 商机

- [ ] 阶段流转正确；
- [ ] 概率只能 0~100%；
- [ ] 赢单/流失能关闭；
- [ ] 加权金额 = 金额 × 概率；
- [ ] 流失原因可记录。

## 5. 指标验收

必须根据 `04_V1指标字典.md` 建立固定测试样本，至少覆盖：

- [ ] 经营销售额；
- [ ] 财务营业收入独立口径；
- [ ] 环比；
- [ ] 同比；
- [ ] 基期为0时显示“-”而非 Infinity；
- [ ] 当前未完月明确标记；
- [ ] 客户变化贡献总和能解释总体变化；
- [ ] 目标完成率；
- [ ] 时间进度；
- [ ] 目标进度差；
- [ ] 剩余工作日日均目标；
- [ ] CRM 登录活跃和有效活跃分开；
- [ ] 沉睡/疑似流失阈值可配置；
- [ ] 前20%客户集中度计算正确。

## 6. 权限安全验收

至少构造：老板A、经理M、销售S1/S2、财务F、管理员Admin。

测试：

- [ ] S1 无法通过改 URL/API 参数读取 S2 客户；
- [ ] S1 无法调用成本/净利润接口；
- [ ] 前端即使被手工篡改也不能绕过后端；
- [ ] Manager 只能看到自己的团队；
- [ ] API Key/AppSecret 不通过 GET API 返回明文；
- [ ] 日志无密码、Secret、Token；
- [ ] 文件路径不能使用 `../` 穿越；
- [ ] 上传非允许文件类型会拒绝。

## 7. BI 页面验收

- [ ] 页面所有指标都能追溯到指标代码/口径；
- [ ] 经营销售额与财务营业收入不会混用标题；
- [ ] 图表空数据有合理空状态，不报错；
- [ ] 金额/比例格式统一；
- [ ] 排行支持明确时间范围；
- [ ] 当前月数据标注截至日期；
- [ ] 贡献分析 TopN 与总变化数字一致；
- [ ] 页面 P95 基本符合架构性能目标。

## 8. 手机端验收

关键页面在常见手机宽度：

- [ ] 可登录；
- [ ] 可看今日待办；
- [ ] 可搜索客户；
- [ ] 可进入客户 360；
- [ ] 可新增跟进；
- [ ] 可完成待办；
- [ ] 可更新商机；
- [ ] 无横向页面级溢出导致主要按钮不可用。

老板复杂 BI 可以桌面体验优先，但基本指标应能在手机查看。

## 9. 备份恢复验收

正式上线前必须演练一次：

1. 生成数据库备份；
2. 使用一个新的 PostgreSQL 容器恢复；
3. 检查用户、客户、跟进、订单、指标；
4. 检查上传文件/附件路径；
5. 记录恢复步骤和耗时。

**未做过恢复演练的备份，只能叫“一个令人安心的文件”。**

## 10. 发布门槛

一个里程碑允许进入下一阶段必须同时满足：

- 自动测试 100% 通过；
- 无已知 P0/P1 缺陷；
- migration 可从空库执行；
- 无权限越权；
- 无重复导入导致数字翻倍；
- 文档与代码保持一致；
- 重要变更写 CHANGELOG；
- 老板/测试用户完成关键流程人工验收。

缺陷等级：

- P0：数据丢失、严重越权、系统不可用；
- P1：核心业务流程错误、BI关键数字错误；
- P2：非核心功能问题、明显体验问题；
- P3：轻微样式/文案。

P0/P1 不得带病进入下一里程碑。
