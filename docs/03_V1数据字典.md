# 松茂经营管理平台 V1 数据字典

**版本：** v0.1  
**日期：** 2026-09-08  
**状态：** 核心数据模型第一版；CRM/销售核心可冻结，采购/库存/应收部分待新样本确认  
**用途：** 作为数据库设计、导入清洗、权限、BI 指标与 Codex 开发的字段级施工依据。

---

## 1. 设计原则

1. **一项业务事实只认一个来源。** 实际成交、商品、采购、库存等认精斗云；跟进、待办、商机认 CRM；财务利润和月末资产负债认财务报表。
2. **内部主键与外部编码分离。** 数据库统一用 UUID；精斗云客户编码、商品编码、单号作为来源键和业务唯一键。
3. **RAW 原始数据不破坏。** 原文件和原始行保留，CORE 层做清洗，BI 层做聚合。
4. **不重复录入。** 销售人员不得在 CRM 再手填真实成交订单、库存、采购等精斗云事实。
5. **历史不能被覆盖。** 客户转交、库存快照、文件导入、活动日志都保留历史。
6. **AI 不参与核心计算。** 数据和指标由程序计算，AI 只读取结构化结果做总结/问答。

## 2. 统一技术口径

| 类型 | 统一规则 |
|---|---|
| 主键 | UUID |
| 时间戳 | PostgreSQL `TIMESTAMPTZ`，统一存时区时间 |
| 月份 | `DATE`，统一保存当月 1 日，如 `2026-09-01` |
| 金额 | `NUMERIC(18,2)`；必要时单价用 `NUMERIC(18,4)` |
| 数量 | `NUMERIC(18,4)` |
| 比例/概率 | 存 0~1 小数，如 73.33% 存 `0.7333` |
| 删除 | 核心业务数据原则上软删除/停用，不物理删除 |
| 来源追溯 | 所有导入事实尽量关联 `import_batch_id` |
| 密钥 | API Key/AppSecret 不明文存储、不回显、不写日志 |

## 3. 数据层与实体总览

**RAW：** `import_batch`、`raw_import_row`  
**INTEGRATION：** `data_source`、`field_mapping`  
**SYSTEM：** `sys_user`、`sys_permission_scope`、`activity_log`  
**CRM：** `customer`、`customer_assignment_history`、`crm_contact`、`crm_tag`、`customer_tag_map`、`crm_followup`、`crm_attachment`、`crm_task`、`crm_opportunity`、`sales_target`  
**ERP CORE：** `product_category`、`brand`、`product`、`product_package`、`supplier`、`sales_order`、`sales_order_line`、`purchase_order`、`purchase_order_line`、`inventory_snapshot`、`receivable_snapshot`  
**FINANCE：** `financial_period`、`financial_metric_monthly`  
**BI：** 由上述 CORE 数据生成聚合表/物化视图。

## 4. `sys_user` — 系统用户

**层级：** SYSTEM  
**状态：** V1  
**用途：** 统一登录账号，承载销售、经理、老板、管理员等角色。

| 字段 | 中文名 | 类型 | 必填 | 来源 | 可编辑 | 键/索引 | 说明 |
|---|---|---|---|---|---|---|---|
| id | 用户ID | UUID | 是 | 系统 | 否 | PK | 内部唯一标识 |
| username | 登录名 | VARCHAR(64) | 是 | 系统管理员 | 管理员 | UK | 建议使用手机号/姓名拼音等稳定账号 |
| display_name | 姓名 | VARCHAR(100) | 是 | 管理员 | 管理员 | - | 如：夏安然 |
| mobile | 手机号 | VARCHAR(32) | 否 | 管理员 | 本人/管理员 | IDX | 用于联系及重复识别，不作为唯一登录条件 |
| email | 邮箱 | VARCHAR(255) | 否 | 管理员 | 本人/管理员 | - | 可选 |
| role_code | 主角色 | VARCHAR(32) | 是 | 管理员 | 管理员 | IDX | sales / manager / owner / finance / admin |
| is_active | 是否启用 | BOOLEAN | 是 | 系统 | 管理员 | IDX | 离职后停用，不物理删除 |
| last_login_at | 最后登录时间 | TIMESTAMPTZ | 否 | 系统自动 | 否 | - | 用于活跃分析 |
| created_at | 创建时间 | TIMESTAMPTZ | 是 | 系统 | 否 | - | 审计 |
| updated_at | 更新时间 | TIMESTAMPTZ | 是 | 系统 | 否 | - | 审计 |

**关键规则：**
- V1 采用“主角色 + 数据范围”即可，不先做复杂 RBAC。
- 停用账号不得删除其历史跟进、商机、任务和客户归属记录。

## 7. `import_batch` — 导入批次

**层级：** RAW  
**状态：** V1  
**用途：** 记录每一次文件导入/重跑，保证可追溯、可去重、可诊断。

| 字段 | 中文名 | 类型 | 必填 | 来源 | 可编辑 | 键/索引 | 说明 |
|---|---|---|---|---|---|---|---|
| id | 批次ID | UUID | 是 | 系统 | 否 | PK | 内部主键 |
| data_source_id | 数据源ID | UUID | 是 | 系统 | 否 | FK | 关联 data_source |
| business_type | 业务类型 | VARCHAR(64) | 是 | 导入选择/自动识别 | 管理员 | IDX | sales / customer / product / purchase / inventory / finance 等 |
| original_filename | 原始文件名 | VARCHAR(255) | 是 | 上传文件 | 否 | - | 原件留档 |
| file_hash | 文件哈希 | VARCHAR(64) | 是 | 系统自动 | 否 | IDX | 用于发现完全重复文件 |
| storage_path | 存储位置 | TEXT | 是 | 系统自动 | 否 | - | NAS/服务器持久化路径 |
| date_from | 数据起始日期 | DATE | 否 | 系统识别 | 管理员 | IDX | 导入覆盖范围 |
| date_to | 数据截止日期 | DATE | 否 | 系统识别 | 管理员 | IDX | 导入覆盖范围 |
| status | 状态 | VARCHAR(24) | 是 | 系统 | 否 | IDX | pending / validating / success / partial / failed / rolled_back |
| total_rows | 原始行数 | INTEGER | 否 | 系统 | 否 | - | 统计 |
| success_rows | 成功行数 | INTEGER | 否 | 系统 | 否 | - | 统计 |
| error_rows | 错误行数 | INTEGER | 否 | 系统 | 否 | - | 统计 |
| imported_by | 导入人 | UUID | 是 | 系统 | 否 | FK | 关联 sys_user |
| started_at | 开始时间 | TIMESTAMPTZ | 否 | 系统 | 否 | - | 日志 |
| finished_at | 结束时间 | TIMESTAMPTZ | 否 | 系统 | 否 | - | 日志 |
| error_summary | 错误摘要 | TEXT | 否 | 系统 | 否 | - | 不得包含密钥 |

**关键规则：**
- 同一文件可重跑，但核心业务表不得重复计数。
- 批次不可静默覆盖；失败时应能定位错误行。

| created_at | 创建时间 | TIMESTAMPTZ | 是 | 系统 | 否 | - | 审计 |
| updated_at | 更新时间 | TIMESTAMPTZ | 是 | 系统 | 否 | - | 审计 |

## 4Z. 去重、关联与覆盖规则

1. **客户：** 精斗云以客户编码为主关联键；CRM 潜客允许无编码，但创建时按标准化客户名、联系人手机号等做重复提醒。潜客一旦在精斗云建档，应绑定到同一 `customer.id`，不能另建第二个正式客户。
2. **商品：** `product_code` 为核心业务唯一键；型号/名称相似只提示疑似重复，不自动合并。
3. **销售单：** `(source_system, order_no)` 唯一；重复导入使用 UPSERT。订单明细优先源明细ID，否则按 `(sales_order_id, line_no)`。
4. **采购单：** 与销售单相同逻辑，按来源+单号去重。
5. **库存：** 按“日期+商品+仓库”保存快照，禁止新导入覆盖历史日期。
6. **财务：** 同一月份允许重导，但必须保留批次；看板只认当前有效/确认版本。
7. **跟进、任务、商机：** CRM 原生数据以系统 UUID 为主，不受精斗云导入覆盖。
