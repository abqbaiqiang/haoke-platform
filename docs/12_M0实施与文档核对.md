# M0 实施与文档核对

日期：2026-09-08。本文件记录工程补充与范围决策，不改变 V1 业务指标。

## 范围

M0 只实现账号、认证、权限基础、布局、迁移、日志、worker 生命周期、测试和部署骨架。
未创建 RAW、CRM、ERP、FIN、BI 表，未实现上传、导入、CRM、图表、AI 或精斗云 API。
目录采用 apps/frontend、apps/backend、apps/worker、tests、scripts、deploy、docs。

## 文档差异与处理

| 项目 | 差异或缺失 | 本轮处理 |
|---|---|---|
| 执行授权 | CODEX_START_HERE 要求确认计划，用户本轮明确无阻塞直接实施 | 按用户直接授权执行，仅 M0 |
| 文档状态 | PRD 仍标草案、下一步设计，CHANGELOG 表示交付包已就绪 | 保留原始文档，按用户 M0 请求与 AGENTS 执行 |
| 项目名称 | 工作区目录叫“好客齐鲁”，交付包叫“松茂” | 产品沿用交付包名称，未自行重命名业务 |
| 字段名 | 07 的 source_customer_code/target_month/action_type 等与 03 的 customer_code/period_month/activity_type 不同 | 后续按字段字典优先；M0 使用 activity_type |
| 密码 | sys_user 未列 password_hash，但安全要求必须存密码哈希 | 增加 password_hash VARCHAR(255)，不在 DTO 中返回 |
| 团队 | 无团队实体、成员关联细节 | 使用既有 sys_permission_scope.scope_value.user_ids 显式 UUID 列表，M0 不建组织树 |
| 多条范围 | 字典未定义一人多范围的合并方式 | M0 每用户一条范围，user_id UNIQUE，避免冲突授权；后续扩展需 migration |
| 管理员范围 | scope_type 无 system，权限矩阵却区分系统管理 | admin 使用 custom 空业务范围；系统账号操作由角色独立控制，不能冒充 owner |
| 登录事件 | 03 示例 login，04 的 CRM_LOGIN_DAY 使用 user_login | 按指标字典保留 user_login 事件；未实现活跃指标 |
| 导入状态 | 03 与 07 批次状态枚举不一致 | M1 前按 03 统一；本轮无导入实现 |
| 商机/跟进 | PRD、05 与 03 阶段/方式名称不同；关闭时间、作废字段不齐 | 对应里程碑前按优先级统一并补迁移，不阻塞 M0 |
| 销售事实 | 指标要求排除取消/作废，但 03 尚未列明确状态字段 | M1 需补来源状态映射与字段，不在 M0 建事实表 |
| 目录 | .env 样例路径与运维宿主示例含义不同 | DATA_ROOT 仅指宿主，UPLOAD_ROOT/BACKUP_ROOT 指容器内部路径 |
| 运行条件 | 本机无 Docker/WSL 可用运行时 | 用户明确同意 Docker 实启、重建、持久化留待 NAS/Docker 环境补验 |

不存在阻塞 M0 的未决业务口径。M1 及以后问题未擅自实现。

## M0 系统模型补充

采用 public schema + sys_ 前缀，activity_log 保留字典原表名。所有实体主键 UUID、时间 TIMESTAMPTZ。

| 表/字段 | 用途与约束 |
|---|---|
| sys_user | 字典原字段 + password_hash；username UNIQUE，role_code CHECK，停用而非删除 |
| sys_permission_scope | self/team/all/custom CHECK；scope_value 为 {"user_ids": ["UUID"]}；一用户一行 |
| sys_session | UUID id、user_id FK、token_hash VARCHAR(64) UNIQUE、created_at/expires_at/revoked_at TIMESTAMPTZ；只保存 HMAC 摘要 |
| sys_login_throttle | key_hash VARCHAR(64) PK、failures INTEGER、window_start TIMESTAMPTZ；数据库行锁保证跨进程限流 |
| activity_log | 字典原字段；Python details 映射数据库 metadata；只记事件与改动字段，不记密码/Token |

team/custom 的成员值由受信任服务端配置，前端不能提交范围。无权限资源统一 404，角色禁止接口 403，未登录/过期 401。
账号资源用于 M0 真实跨用户读写验收，不引入 CRM 客户：owner 查看全部，manager 团队，sales 自己，finance 指定授权，admin 系统范围；个人联系方式仅本人或 admin 可改。

## 认证和日志

- Argon2id 随机盐密码哈希；初始化密码至少 12 字符，拒绝占位符。
- 48 随机字节 Cookie Session，HttpOnly / SameSite=Lax，生产 Secure，默认 8 小时。
- 所有写请求（含登录）必须 Origin 与 APP_BASE_URL 一致；同源代理，无宽泛 CORS。
- 退出立即撤销服务端会话；重新登录轮换会话；每次请求重新检查停用状态与当前权限。
- 默认每账号 15 分钟最多 5 次失败；数据库持久限流，未知账号也受限。
- 生产要求 HTTPS 和至少 32 字符随机主密钥，关闭调试与 OpenAPI。
- 结构化日志仅记录服务器生成的 request_id、方法、状态码，不记录请求体、查询串、Cookie 或异常参数。
- 登录和退出写 activity_log；账号 CLI 的停用、密码重置撤销旧会话并记审计。

## 迁移影响

0001_m0 从空库创建 5 张系统表，不涉及现有业务数据。
downgrade base 会删除这些系统表，仅允许隔离测试库使用；正式环境发布前备份，回退优先恢复备份，禁止以降级清库解决问题。
未使用 create_all 代替迁移。测试使用真实 PostgreSQL 独立 *_test 数据库中的随机 schema，测试完成仅清理自己创建的 schema。

## 版本和资料

Python 3.14、Next.js 16.3.4、React 19.2.8、FastAPI 0.141.1、SQLAlchemy 2.0.52、PostgreSQL 18.4。
Python 依赖在 requirements.lock / requirements-test.lock 固定，前端 package-lock.json 固定传递依赖。
版本选取核对 [Next.js 安装文档](https://nextjs.org/docs/app/getting-started/installation)、[FastAPI 发布记录](https://fastapi.tiangolo.com/release-notes/) 及包仓库稳定版本。
本地 Windows PostgreSQL 使用 @embedded-postgres/windows-x64 18.4.0-beta.17 包中的 PostgreSQL 18.4 二进制，仅作开发验收；生产使用官方 PostgreSQL Docker 镜像。
