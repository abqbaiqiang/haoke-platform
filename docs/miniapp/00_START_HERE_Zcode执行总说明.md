# 1. 一句话产品定义

这是给销售人员外出时使用的**移动 CRM 执行工具**。

它解决四件事：

- 到客户门口前，30 秒内知道“该找谁、上次聊了什么、我答应过什么、当前有什么机会”；
- 离开客户后，用语音、照片或文字在 1 分钟左右完成本次跟进记录；
- 自动形成下一步待办，防止承诺和跟进丢失；
- 根据当前位置查看附近已有客户，方便顺路拜访。

它**不是 PC 管理后台的缩小版**。

# 3. 不可违反的产品规则

## 3.1 小程序禁止新增客户

小程序不提供：

- 新增客户入口；
- 扫名片自动建客户；
- 潜客录入；
- 手工创建精斗云客户。

客户来源继续服从现有系统规则，以精斗云导入 / 当前 CRM 已有客户为准。

PC 端已经存在的客户创建能力不要因为本项目而删除。这里只是**不向小程序暴露创建能力**。

## 3.2 不做 BI，不做销售业绩大屏

小程序不展示：

- 销售额；
- 毛利率；
- 同比环比；
- 目标完成率；
- 排名；
- 经营驾驶舱。

“本周拜访、待办、记录”这类**工作过程数量**可以少量出现，但不能演变成 KPI 看板。

## 3.3 不重复建设 CRM

现有 Contact、Followup、Task、Opportunity、Customer、订单事实等模型能复用的必须复用。

移动端可以增加：

- 移动端专用聚合 API；
- 地图坐标字段；
- 临时媒体上传；
- 音频转写；
- AI 整理快照；
- 小程序认证适配。

不得复制出 `mini_customer`、`mini_followup`、`mini_task` 之类与现有业务表平行的数据孤岛。

# 4. 现有代码已经具备的能力

当前仓库已有：

- `Customer` 客户主数据，且已有 `company_address`；
- `Contact` 联系人；
- `Followup` 跟进记录；
- `FollowupAttachment` 跟进附件，当前偏图片场景；
- `Task` 待办；
- `Opportunity` 商机；
- 客户详情聚合，已包含联系人、跟进、待办、商机、事件、订单和销售摘要；
- `save_followup()` 已实现“填写下一步行动 + 下次跟进时间后，自动生成/更新关联待办”；
- 角色权限体系；
- 浏览器用户名密码登录和 Session；
- PostgreSQL + Alembic；
- 文件上传目录和现有图片附件逻辑。

因此本项目的原则是：**移动适配和能力补全，不重新发明业务。**

# 5. 推荐技术方案

## 小程序端

- Taro 4.x
- React
- TypeScript
- SCSS
- 微信小程序作为第一目标平台
- 新建 `apps/miniapp/`

选择 Taro 的理由：当前 PC 端已经是 React + TypeScript，维护思路统一；Taro 已提供微信小程序录音、地图、媒体选择等适配能力。

## 后端

继续使用现有：

- FastAPI
- SQLAlchemy
- Pydantic
- PostgreSQL
- Alembic
- 现有 Worker

新增 `mobile_api.py / mobile_schemas.py` 等薄适配层，不复制核心 CRM Service。

# 7. 对 Skill / MCP 的结论

本项目**不把 MCP 当成 UI 质量的核心解决方案**。

MCP 适合让 AI 查询外部设计稿、组件文档或系统，不会自动解决“页面层级乱、间距乱、组件不统一”。

本项目 UI 质量主要靠：

1. 六张视觉参考图；
2. 固定 Design Token；
3. 固定公共组件；
4. 明确页面结构和尺寸；
5. 截图对比验收；
6. Zcode 强规则文件。

如果 Zcode 支持项目 Skill / Rule，可把 `04_UI设计系统与Zcode强约束.md` 作为长期项目规则加载。

NutUI 的 AI Coding / Skill / MCP 可以作为**组件 API 查询辅助**，但当前不建议把 NutUI Beta 或任何 MCP 设成生产运行依赖。尤其当前项目使用较新的 React 版本，先做兼容性 POC，再决定是否引入。

Figma MCP 当前也不是必需，因为目前手里是已经确认过的 PNG 效果图，而不是完整 Figma 组件库。没有源设计系统时，MCP 不会凭空变出精确设计。

# 9. 开发顺序

必须遵守：

**先 UI 骨架和组件 → 再接只读 CRM 数据 → 再跟进写入 → 再媒体/AI → 再地图 → 再全面测试。**

不要六个页面同时边写 UI 边改数据库边接 AI。那种“全面开花”通常最后开成一片错误日志。

详细任务见 `06_Zcode开发任务拆解与验收标准.md`。

```text
- UI 严格遵守 04_UI设计系统与Zcode强约束.md；
- 每个阶段完成后先测试和提交，再进入下一阶段；
- 不允许因为“方便”关闭 Origin/CSRF、权限或文件校验。

先执行 06 文档中的 Phase 0，不要一次性实现全部功能。
```

# 11. 完成标准

V1.0 只有在以下全部成立时才算完成：

- 六个业务页面均实现；
- 小程序无新增客户入口和 API；
- 销售权限后端有效；
- 客户详情能展示联系人、拜访前速览和统一动态时间线；
- 能录音、转文字、AI 整理、编辑确认并保存；
- 能拍照上传并绑定跟进；
- 保存下一步行动能生成现有 Task；
- 附近客户地图能按授权范围展示客户并导航；
- 不持久化销售员实时位置；
- 弱网或上传失败不会静默丢记录；
- PC 原功能回归通过；
- 小程序 `build:weapp` 通过；
- 后端新增测试通过；
- 真机测试通过；
- UI 截图与 6 张参考图的布局层级一致。
