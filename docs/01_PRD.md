# 松茂经营管理平台 V1 产品需求文档（PRD）

**版本：** v0.1  
**日期：** 2026-09-08  
**状态：** 第一版需求草案，待评审冻结  
**项目定位：** 在不替代、不改动精斗云的前提下，建设“轻量 CRM + 数据中台 + BI 经营驾驶舱”的统一 Web 系统。

---

## 1. 项目背景

公司目前已经使用精斗云承担进销存及部分经营数据管理，已存在销售、采购、商品、客户、供应商、库存、收付款等业务数据，同时每月有利润表、资产负债表等财务报表。

当前主要问题不是“没有数据”，而是数据分散：

- 精斗云能记录已经发生的交易，但难以完整记录销售过程；
- 销售人员的客户跟进、关系人、意向、待办、商机等信息缺少统一入口；
- 财务报表、进销存、CRM 过程数据无法统一分析；
- 老板需要的是“发生了什么、为什么、哪里有风险、下一步关注什么”，而非单纯查看多个系统中的原始数据；
- 现阶段暂不接精斗云 API，可通过 Excel/CSV 手动同步，后续预留 API 对接能力。

因此 V1 不建设新的 ERP，不替代精斗云，而是在其上方建设统一经营管理平台。

---

## 2. 项目目标

### 2.1 核心目标

1. 为销售人员提供一个简单、低负担、可日常使用的 CRM 工作入口；
2. 将精斗云导出数据、CRM 数据、财务报表导入同一数据体系；
3. 为老板和管理层提供统一 BI 经营驾驶舱；
4. 支持销售目标、过程执行、客户经营、业绩结果的联动分析；
5. 核心分析不依赖 AI，AI 作为可选增强层；
6. 系统支持 Docker Compose 部署，可部署在绿联 NAS，也可未来迁移到阿里云等普通 Linux 服务器；
7. 从第一版预留精斗云 API 配置与数据连接器能力，未来无需推翻系统即可自动同步。

### 2.2 V1 成功标准

V1 上线后应达到：

- 销售人员每天愿意打开系统处理客户与待办，而不是为了“填日报”被迫使用；
- 销售人员无需重复录入精斗云中的销售订单、商品、采购等事实数据；
- 老板能在一个网站中查看销售、客户、商品、业务员、CRM 活跃、财务等核心信息；
- 每月、每日更新数据后，BI 自动更新同比、环比、趋势与异常；
- 同一指标有明确唯一的数据来源和计算口径；
- 数据导入可追溯、可去重、可重跑，不能因重复上传而重复计算；
- 核心业务数据可备份并可迁移。

## 3. 产品边界

### 3.1 精斗云继续负责

精斗云仍是以下业务事实的主要来源：

- 商品档案
- 客户基础档案
- 供应商
- 销售订单
- 销售退货
- 采购订单
- 采购退货
- 库存
- 收款/付款（以实际可导出字段为准）
- 应收应付（以实际可导出字段为准）

本项目 **不在 V1 中重写上述 ERP 功能**。

### 3.2 CRM 负责

CRM 只负责“销售过程”和“客户关系”：

- 客户负责人
- 客户联系人/关系人
- 客户标签
- 客户备注
- 跟进记录
- 跟进结果
- 资料/报价发送记录
- 下次跟进时间与下一步动作
- 今日/本周待办
- 商机及商机阶段
- 客户转交/公海
- 客户操作时间线
- 销售目标与个人工作台

### 3.3 BI 负责

BI 是统一看台，负责把精斗云、CRM、财务数据串起来：

- 经营总览
- 销售分析
- 客户分析
- 商品分析
- 业务员分析
- CRM 过程分析
- 采购分析
- 供应商分析
- 库存分析
- 财务分析
- 应收与现金分析
- 风险预警
- 目标完成与月底预测

## 4. 用户角色与权限

### 4.1 普通销售

主要目标：管理自己的客户和今天要做的事。

可见：

- 我的工作台
- 我的客户
- 我的联系人
- 我的跟进记录
- 我的今日/本周待办
- 我的商机
- 我的销售目标与完成率
- 自己相关的销售数据

默认不可见：

- 全公司财务数据
- 其他销售的敏感客户数据
- 公司级成本/利润（是否显示个人客户毛利后续单独确定）
- 系统配置

### 4.2 销售经理/管理人员

在销售权限基础上增加：

- 团队销售目标
- 团队客户
- 团队商机
- 团队 CRM 活跃与有效动作
- 跟进完成情况
- 超期客户
- 团队销售分析

### 4.3 老板账号

可查看所有业务与 BI 模块，包括：

- 全公司经营总览
- 销售/客户/商品/业务员
- CRM 团队执行
- 采购/供应商/库存
- 财务/现金/应收
- 风险中心
- 系统关键日志

### 4.4 系统管理员

负责：

- 用户账号
- 角色权限
- 数据导入
- 数据源配置
- 字段映射
- API 配置
- AI 配置
- 同步日志
- 备份与系统设置

## 5. CRM V1 功能需求

## 5.1 销售个人工作台

销售登录后首页应优先展示“今天要做什么”，而不是复杂菜单。

### 关键区域

1. **本月业绩目标**
   - 月度销售目标
   - 当前实际销售额
   - 目标完成率
   - 时间进度
   - 完成率相对时间进度（超前/落后）
   - 剩余目标
   - 剩余工作日
   - 日均需要完成金额

2. **今日待办**
   - 今日应跟进客户
   - 已报价待反馈
   - 约定今日联系
   - 逾期未完成任务
   - 系统推荐任务
   - 老板/经理分配任务
   - 员工自己创建任务

3. **本周待办**
   - 本周所有计划事项
   - 完成/未完成状态
   - 可打勾完成

4. **商机概览**
   - 商机数量
   - 商机金额
   - 高概率商机金额
   - 即将到预计成交日期的商机

5. **最近客户**
   - 最近跟进
   - 最近访问
   - 最近成交

### 待办原则

不要求销售手写日报。系统根据打勾、跟进、商机、任务自动形成每日工作摘要。

---

## 5.2 客户管理

### 客户基本信息

客户主数据原则上来自精斗云；CRM 可补充销售过程字段。

建议字段：

- 客户编码
- 客户名称
- 客户类型
- 客户负责人
- 客户级别
- 状态（潜在/活跃/沉睡/流失等）
- 联系方式（如主档可获取）
- 结算/账期信息（如主档可获取）
- 客户标签
- 客户备注

### 客户归属

- 每个客户可指定负责人；
- 管理员/经理可转交客户；
- 转交后历史跟进、联系人、订单关联不得丢失；
- 转交行为进入操作时间线。

### 客户公海

V1 可提供基础公海能力：

- 无负责人客户可进入公海；
- 允许有权限人员领取；
- 长期无人跟进自动进入公海的规则先预留，不默认启用。

### 重复客户检测

创建 CRM 临时客户/潜客时，根据以下信息进行重复提醒：

- 客户名称
- 联系电话
- 联系人电话
- 其他可用唯一信息

重复检测为“提醒”，不在不确定时自动合并。

## 5.3 客户标签

支持一个客户多个标签。

典型标签包括但不限于：

- 中国银行
- 工商银行
- 农业银行
- 太平保险
- 烟草
- 礼品公司
- 企业福利
- 一件代发
- 国企客户
- 高端礼赠

要求：

- 管理员可维护公共标签；
- 是否允许销售自建标签由后台配置；
- 标签可用于客户筛选、BI 分析和后续系统推荐；
- 不应把所有客户特征都塞进自由备注。

---

## 5.4 联系人与公司关系人

一个客户可存在多个联系人/关系人。

字段建议：

- 姓名
- 角色
- 电话
- 微信/其他联系方式
- 是否关键决策人
- 是否主要联系人
- 备注

角色支持：

- 老板
- 老板娘
- 采购
- 财务
- 行政
- HR
- 项目负责人
- 决策人
- 使用人
- 介绍人
- 自定义角色

支持记录关系性备注，例如“采购负责日常询价，老板最终拍板”。

---

## 5.5 客户跟进

每次跟进尽量采用“结构化选择 + 简短备注”，降低员工录入负担。

### 跟进方式

- 微信
- 电话
- 面谈
- 拜访
- 报价
- 发送资料
- 其他

### 跟进结果

- 已接通/已沟通
- 沟通顺利/有明确需求
- 暂无需求
- 未接通
- 已加微信
- 已发资料
- 已报价
- 等客户回复
- 约好下次联系
- 明确拒绝
- 已成交
- 已流失
- 其他

### 其他字段

- 跟进内容简短备注
- 是否发送资料
- 是否发送报价
- 下次跟进时间
- 下一步动作
- 关联商机（可选）

原则：跟进记录一旦创建，应保留历史；修改需留操作日志。

---

## 5.6 今日/本周待办

待办来源分为三类：

1. 系统自动推荐；
2. 销售自己添加；
3. 老板/经理分配。

系统自动推荐场景示例：

- 客户达到约定下次跟进时间；
- 报价后若干天无后续；
- 高价值客户超过指定天数未跟进；
- 商机预计成交日期临近；
- 有逾期未完成任务。

任务字段：

- 标题
- 关联客户
- 关联商机
- 负责人
- 截止日期
- 优先级
- 来源
- 状态（待处理/完成/取消）
- 完成时间
- 简短结果

完成任务以“打勾”为主，不要求长篇日报。

## 5.7 商机管理

V1 使用简单销售阶段，不做复杂 CRM 流程。

建议阶段：

1. 初步沟通
2. 有明确需求
3. 已发方案/报价
4. 谈判/等待反馈
5. 高概率成交
6. 已成交
7. 已流失

字段：

- 商机名称
- 客户
- 负责人
- 预计金额
- 阶段
- 成交概率（可选/按阶段默认）
- 预计成交日期
- 主要需求
- 备注
- 流失原因

实际成交金额最终以精斗云销售数据为准，不要求员工重复填写正式成交订单。

客户详情应整合：

- 基本资料
- 标签
- 联系人/关系人
- 客户备注
- 历史跟进
- 当前待办
- 商机
- 精斗云销售历史
- 主要购买商品
- 最近成交时间
- 应收/回款信息（有数据时）
- 客户时间线

精斗云同步字段原则上只读，CRM 字段可按权限编辑。

## 5.9 CRM 使用与活动日志

系统需要记录销售是否真实使用 CRM，但不做无意义的“鼠标监控”。

### 登录/活跃记录

- 当日是否登录
- 首次登录时间
- 最后活跃时间
- 本月 CRM 活跃工作日
- 连续未登录天数

### 有效业务动作

至少记录：

- followup_create
- followup_update
- task_complete
- opportunity_create
- opportunity_update
- customer_update
- contact_create/update
- customer_transfer

老板/经理看板应区分：

- “登录过”
- “产生有效业务动作”
- “产生有效客户跟进”

不把页面在线时长、鼠标行为作为绩效依据。

## 6. 销售目标与团队管理

后台支持按月份设置业务员目标。

V1 至少支持：

- 销售额目标
- 可选：毛利目标
- 可选：新增成交客户目标

销售完成值来自精斗云导入数据。

### 团队执行驾驶舱

老板/经理查看：

- 每人月度目标
- 实际销售额
- 完成率
- 时间进度
- 超前/落后
- CRM 活跃天数
- 有效跟进客户数
- 有效跟进次数
- 待办完成率
- 超期待办
- 商机储备
- 高概率商机
- 新增客户
- 月底完成预测（后续迭代可增强）

目标是同时看到“结果、过程、未来储备”，而不是只看销售额排名。

## 7.7 财务与经营分析

财务数据来自月度利润表与资产负债表。

V1 支持：

- 营业收入
- 成本
- 毛利
- 费用
- 净利润
- 净利率
- 现金余额
- 应收
- 应付
- 借款
- 库存
- 同比/环比
- 月度趋势

### 经营与财务口径并存

系统明确区分：

- **经营销售额：** 来源精斗云，用于客户、商品、业务员分析；
- **财务营业收入：** 来源利润表，用于正式财务结果分析。

同时提供“经营销售额 vs 财务营业收入”的勾稽差异，不强行把两个口径混成一个数字。

---

## 7.8 风险中心

V1 规则型预警至少预留：

- 销售额大幅下降
- 重点客户采购下降
- 重点客户长时间未跟进
- 报价后长期无后续
- 商机长期不更新
- 毛利异常（数据条件满足时）
- 应收逾期（数据条件满足时）
- 现金快速下降
- 库存异常（数据条件满足时）

规则阈值应后台可配置，而不是写死在代码中。

## 8.2 手工导入要求

V1 必须支持：

- xlsx
- xls（如技术方案稳定支持；否则明确提示转换 xlsx）
- csv

导入流程：

1. 用户上传文件；
2. 系统识别数据类型；
3. 校验字段；
4. 显示导入预览；
5. 校验主键/重复；
6. 新增或更新；
7. 生成导入结果；
8. 记录日志；
9. 原始文件留档。

不得因重复上传全量销售文件导致订单重复。

---

## 8.3 数据三层架构

### RAW 原始层

保存每次导入原始文件及解析结果，用于追溯。

### 标准业务层

统一实体，例如：

- Customer
- Contact
- Product
- Supplier
- SalesOrder
- SalesOrderLine
- PurchaseOrder
- PurchaseOrderLine
- InventorySnapshot
- FollowUp
- Task
- Opportunity
- SalesTarget

### BI 分析层

预聚合常用指标，避免每次打开页面重新计算全部历史明细。

## 11. 精斗云 API 预留

V1 不要求完成正式 API 对接，但架构必须允许未来无重构接入。

### 后台预留“数据集成 > 精斗云”

配置项按实际官方接口最终调整，页面预留：

- API 地址
- AppKey
- AppSecret
- 企业/账套标识
- Token/授权信息
- 测试连接
- 启用/停用
- 同步模块
- 同步频率
- 立即同步
- 重跑指定日期
- 同步日志

### 连接器原则

系统内部不直接依赖精斗云字段命名。

采用统一连接器概念：

- ExcelConnector
- CSVConnector
- JingdouyunConnector（预留）
- FutureConnector

未来 API 接入只替换/新增数据获取方式，不改变 CRM 和 BI 核心模型。

## 13. 技术与部署要求

### 13.1 部署原则

- Web 系统，浏览器访问；
- 不要求开发原生 App；
- Docker Compose 标准化部署；
- 不绑定绿联 NAS 专有功能；
- 可从 NAS 平滑迁移到普通 Linux 云服务器；
- 数据目录与容器分离，必须持久化。

### 13.2 V1 推荐部署环境

优先：绿联 NAS（DXP4800 系列）作为公司内部第一版服务器。

未来可迁移：阿里云等 Linux 云服务器。

### 13.3 基础服务建议

最终技术选型在技术设计阶段冻结，当前方向：

- PostgreSQL 数据库
- Python 后端服务
- Web 前端
- Docker Compose
- 反向代理/HTTPS（外网正式访问时）

### 13.4 安全要求

- 密码不得明文保存；
- API Secret/API Key 不得写死在代码；
- PostgreSQL 不直接暴露公网；
- 角色权限后端强校验，不能只靠前端隐藏；
- 关键修改留操作日志；
- 数据库定期自动备份；
- 上传文件限制类型和大小；
- 备份与恢复流程必须有文档。

## 14. V1 明确不做

- 替代精斗云的 ERP 功能
- 销售开单/采购开单
- 完整仓库管理
- 完整财务记账系统

- 完整合同管理
- 专业呼叫中心

- 鼠标/屏幕/在线时长监控
- 原生 iOS/Android App
- 微信自动抓取聊天记录
- 一次性接入所有外部 API

后续真实需要时再迭代。

## 15. 关键业务规则

1. 精斗云事实数据不允许 CRM 重复手工录入；
2. 正式销售额以精斗云订单为经营口径；
3. 财务营业收入以利润表为财务口径；
4. CRM 商机金额属于预测，不等于实际销售额；
5. 客户跟进应轻量化，结构化选择优先于长文本；
6. 员工使用情况看“有效业务动作”，不以单纯在线时长衡量；
7. 历史订单毛利不能用当前最近采购价直接替代历史真实成本；
8. 所有 BI 指标在《指标字典》中定义唯一口径后方可正式开发；
9. 所有重要实体在《数据字典》中定义后方可建表；
10. API 对接属于数据连接层，不允许把精斗云耦合进整个系统。
