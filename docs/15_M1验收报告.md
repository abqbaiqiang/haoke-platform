6. 数据中心包含创建来源、人员映射、上传/预检/确认、分页历史/原始行、销售月度核对/订单明细、财务月度核对/期间确认；适配桌面和手机。
7. owner 全部查看；manager 团队、sales 本人、finance 授权销售范围由后端执行。数据中心原件只给 owner/admin，finance 仅获财务原件；admin 管系统和导入，不自动获得经营汇总。CRM 工作台并未开放。

## 文档差异和实施选择

- 来源编码作为 CORE `source_system` 的账套命名空间，保留来源键；新增 `entity_name` 约束财务主体，避免跨账套同编码覆盖。
- 每批保存不可变 JSON 字段映射版本及人员映射快照，代替本阶段逐字段配置表单；前端提供可选列号映射，标准导出无需配置。模板变更不能悄悄改旧批次。
- 销售明细唯一键增加版本，当前行用 `is_active` 标识；当前订单头与旧批次快照共同保留变更证据。客户/商品仅落 M1 必需标准字段，可选联系方式/包装/分类等保留在原件与 RAW，相关 CRM/品牌分类实体留在后续阶段。
- `financial_period` 按来源与月份唯一；财务值遵循字典专门字段 `NUMERIC(20,2)`，销售金额 `NUMERIC(18,2)`、数量/单价四位，API 返回金额字符串。
- 汇总直接从已提交 CORE 做 PostgreSQL Decimal 聚合，所以确认后即时更新，无陈旧缓存。M1 暂未建立物化 BI 表；后续性能需求出现后再迁移。指标名为技术核对 `DQ_SALES_RECON`，不替代指标字典 `EXEC_SALES_AMT`。没有推断作废、退货、当前应收或历史成本。
- 本阶段限额文件在后端线程池同步解析/确认；独立 worker、Compose 配置和健康检查继续保留，导入任务队列尚未启用。大文件和异步重试不在本次已验收范围。
- 财务金额列遇公式会拒绝，辅助公式仅作为原始追溯，不在服务端执行。年初不是上月；缺 7 月不会生成环比。

以上是 M1 的物理实现及阶段范围补充，未修改业务指标公式。业务未决项继续遵循 AGENTS 的“明确标记，不阻塞无关模块”。

## 后续人工使用反馈：查看订单交互修复

用户点击“查看订单”看似无反应。实际请求返回 200 和 30 张订单，但结果位于九个月汇总表下方，标题在 800 像素高视口之外（约 y=1213）。原 E2E 只验证元素存在且可点击，会自动滚动，未覆盖用户点击后结果是否立刻出现在视口内。

改为原生 modal 窗口，直接显示月份、加载/失败/空状态、分页及明细。进入明细后可以返回原分页；关闭或 Escape 返回触发按钮，关闭时终止旧请求。新增长表场景下 `toBeInViewport` 断言和失败重试测试。只修改前端交互，无迁移、指标公式或数据权限变更。本机真实订单已验证，98 项后端测试及工程构建继续通过；浏览器最终结果见 TASK_STATUS。
